Guide d'utilisation — Activités courantes¶

Ce guide décrit les activités principales que les utilisateurs finaux effectuent dans le système Equipe Laurence.

🔄 Synchronisation des données (Nethris → SharePoint)¶

Vue d'ensemble¶

La synchronisation automatique transfère les rapports automatisés de l'API Nethris HR vers une bibliothèque de documents SharePoint toutes les minutes et exécute la copie seulement si nécessaire. Ce processus est entièrement automatisé et ne requiert aucune intervention manuelle.

Quand a lieu la synchronisation?¶

  • Fréquence : Toutes les minutes
  • Exécution : La copie ne s'exécute que s'il y a de nouveaux rapports disponibles
  • Durée estimée : 5 à 15 minutes selon le nombre de rapports
  • Redémarrages automatiques : En cas d'erreur, Azure Functions réessaie automatiquement avec une stratégie exponentielle

Où sont stockés les fichiers?¶

Les rapports synchronisés sont déposés dans SharePoint selon la structure suivante :

FSources/
└── Nethris/
    └── {NomRapport}_{yyyyMMdd_HHmmss}.{extension}

Exemple : FSources/Nethris/PayrollReport_20260519_030000.xlsx

Comment savoir si la sync a réussi?¶

  1. Via SharePoint : Consultez la bibliothèque FSources/Nethris/ et vérifiez la présence des fichiers
  2. Via Application Insights (pour administrateurs) : Les traces de sync sont enregistrées et consultables dans le portail Azure
  3. En cas de problème : Contactez l'équipe technique — les journaux détaillés contiennent le diagnostic

Protection contre les doublons¶

  • Un ledger de synchronisation (basé sur Azure Table Storage) garantit qu'aucun rapport n'est uploadé deux fois
  • Si un rapport a déjà été synchronisé, il est automatiquement ignoré lors du prochain cycle
  • Les erreurs partielles n'affectent pas les synchronisations futures : seuls les rapports défaillants sont réessayés

📱 Envoi de SMS d'urgence¶

Vue d'ensemble¶

Le module SMS d'urgence permet d'envoyer rapidement des messages de notification à des groupes de destinataires via Twilio. Ce service respecte les normes de conformité CASL, TCPA et Loi 25 (PIPEDA).

L'accès à cette fonctionnalité nécessite systématiquement une authentification Entra ID (jeton Bearer valide), indépendamment de tout groupe de sécurité. Contactez votre administrateur Entra ID si vous n'avez pas de compte dans le locataire de l'organisation.

Authentification requise¶

Avant de pouvoir envoyer des SMS, vous devez :

  1. Posséder un compte Entra ID dans le locataire de votre organisation
  2. Disposer d'un token Entra ID valide pour signer vos requêtes

Contactez votre administrateur Entra ID si vous n'avez pas de compte dans le locataire.

Qui peut envoyer des SMS?¶

  • Tout utilisateur authentifié via Entra ID dans le locataire de l'organisation
  • L'envoi de SMS est protégé par authentification Entra ID (jeton Bearer JWT)

Comment envoyer un SMS d'urgence?¶

Via le formulaire web¶

C'est la méthode recommandée pour les utilisateurs. Aucune connaissance technique n'est requise.

  1. Ouvrez le formulaire dans un navigateur web : 
    https://<function-app>.azurewebsites.net/api/notifications/sms/form
  2. Authentifiez-vous avec vos identifiants Entra ID quand le navigateur le demande
  3. Sélectionnez le bureau dans la liste déroulante — la liste est peuplée automatiquement à partir de BaseTi
  4. Rédigez le message dans la zone de texte (5 caractères minimum)
  5. Cliquez sur Envoyer les SMS
  6. Une réponse JSON s'affiche indiquant le nombre de SMS envoyés, échoués et l'identifiant d'audit

⚠️ Les SMS sont envoyés à tous les employés du bureau sélectionné ayant un numéro mobile valide et n'ayant pas retiré leur consentement (STOP).

Erreurs d'authentification possibles :

  • Pas de token fourni → Vous devez vous authentifier via Entra ID
  • Token expiré → Rechargez la page pour vous ré-authentifier
  • Pas membre du groupe autorisé → Contactez votre administrateur pour être ajouté au groupe SMS

Via l'API HTTP (pour intégrations)¶

Envoyez une requête POST avec un jeton Bearer Entra ID :

POST /api/notifications/sms/send-by-bureau HTTP/1.1
Authorization: Bearer <token-entra-id>
Content-Type: application/x-www-form-urlencoded

locationCode=MTL&messageBody=Alerte+urgente+%3A+%C3%A9vacuation+imm%C3%A9diate.

Pour obtenir un token Entra ID :

# Via Azure CLI (développement local)
az account get-access-token --resource api://votre-client-id --query accessToken -o tsv

# Via cURL (client credentials flow)
curl -X POST "https://login.microsoftonline.com/<tenant-id>/oauth2/v2.0/token" \
  -d "client_id=<client-id>" \
  -d "client_secret=<client-secret>" \
  -d "scope=api://votre-client-id/.default" \
  -d "grant_type=client_credentials"

Réponse en cas de succès (200 OK) :

{
  "locationCode": "MTL",
  "totalEmployees": 5,
  "sent": 4,
  "failed": 1,
  "auditId": "3fa85f64-...",
  "details": [
    {
      "employeeNumber": "000123",
      "name": "Jean Tremblay",
      "phone": "****7890",
      "status": "sent",
      "messageId": "twilio-msg-123"
    },
    {
      "employeeNumber": "000124",
      "name": "Marie Côté",
      "phone": "****1234",
      "status": "failed",
      "error": "InvalidPhoneNumber"
    }
  ]
}

Erreurs possibles :

  • 401 Unauthorized — Token manquant ou invalide
  • 403 Forbidden — Vous n'êtes pas membre du groupe SMS autorisé

Résolution des destinataires¶

Les destinataires sont résolus à partir de BaseTi (base de données interne) par code de bureau. Le système :

  1. Récupère tous les employés du bureau sélectionné dans BaseTi
  2. Filtre ceux ayant un numéro mobile valide et éligibles aux SMS
  3. Exclut les employés ayant répondu STOP
  4. Envoie le SMS via Twilio

⚠️ Important : Assurez-vous que tous les employés sont inscrits dans BaseTi avec un numéro de téléphone mobile valide.

Limitations et quotas¶

Aspect Limite
Longueur maximale du message 160 caractères (SMS standard) ou 153 si caractères spéciaux
Nombre de destinataires par envoi Pas de limite théorique, mais limité par le quota de l'API
Temps de livraison 1–5 secondes en moyenne
Historique conservé 90 jours

Conformité et consentement¶

Avant d'envoyer des SMS, assurez-vous que :

  • ✅ Les destinataires ont donné leur consentement préalable à recevoir des SMS
  • ✅ Les messages respectent les conditions de CASL/TCPA (pas d'abus, horaires respectés)
  • ✅ Les données personnelles sont traitées selon PIPEDA (Loi 25)
  • ✅ Un log d'audit enregistre chaque envoi et la réponse

Que se passe-t-il en cas d'erreur?¶

Erreur Cause probable Action
destinataire non trouvé Le nom n'existe pas dans BaseTi Vérifiez l'orthographe ou l'ID BaseTi
numéro invalide Le numéro enregistré est mal formé Mettez à jour le dossier dans BaseTi
quota dépassé Trop de SMS envoyés cette heure Attendez ou contactez l'administrateur
erreur réseau Problème temporaire de connectivité L'envoi sera réessayé automatiquement

📊 Surveillance et rapports¶

Où consulter l'état des activités?¶

  • Synchronisation Nethris : Bibliothèque SharePoint Nethris/Raw/ + journaux Application Insights
  • Envois SMS : Logs d'audit dans Table Storage + rapports d'Application Insights
