Audit de configuration et secrets — EquipeLaurence¶

Date de l'audit : 2026-05-11
Système : Azure Function App synchronisant les rapports Nethris vers SharePoint
Portée : Toutes les clés de configuration, valeurs secrètes, variables d'environnement et leur traçabilité complète

Statut de la mise à jour (revue d'exactitude) : ce document est un instantané de l'audit du 2026-05-11. Les écarts suivants ont été constatés par rapport au code et à l'infrastructure actuels ; en cas de doute, infra/main.bicep, infra/modules/*.bicep et src/EquipeLaurence.Functions/FunctionAppStartup.cs font foi :

  • Les paramètres métier (Nethris__*, SharePoint__*, Ledger__*) ne sont plus dupliqués en paramètres directs du Function App : functionApp.bicep ne définit que les valeurs d'amorçage (AppConfiguration__Endpoint, Nethris__SyncSchedule, Sms__Enabled, MICROSOFT_PROVIDER_AUTHENTICATION_SECRET, AzureWebJobs.*.Disabled, stockage et télémétrie). Tout le reste provient d'App Configuration.
  • Le fournisseur SMS est piloté par Sms:Provider (Twilio, Acs ou Disabled) et des clés Twilio:* existent ; FunctionAppStartup.IsSmsEnabled() et la lecture de Sms:Enabled par le code n'existent plus (GetSmsProvider les remplace). Sms__Enabled n'est plus qu'un paramètre Bicep/Function App (activation des fonctions SMS).
  • AZURE_TENANT_ID, AZURE_CLIENT_ID et AZURE_CLIENT_SECRET sont provisionnés dans App Configuration (le secret via une référence Key Vault, secret azure-ad-client-secret) et servent à BuildGraphCredential (mode ClientSecret, par défaut) ; ils ne sont pas réservés au développement local.
  • Options supplémentaires : NethrisRetryOptions (Nethris:Retry), BaseTiOptions (BaseTi), SmsOptions (Sms), SharePoint:AuthMode, AzureAd:Instance, AzureAd:AuthorizedGroupId (optionnel, non lu par le code actuel).
  • Les secrets GitHub réellement utilisés par les workflows sont listés dans la section « Inventaire des secrets et variables GitHub Actions » ci-dessous (corrigée).

Sommaire exécutif¶

Le système EquipeLaurence gère la configuration et les secrets à travers plusieurs sections de configuration (Nethris, SharePoint, Ledger, BaseTi, Sms, Twilio/Acs, AzureAd), plus de 10 secrets GitHub Actions et plusieurs paramètres Bicep spécifiques aux environnements. La configuration transite par 4 chemins distincts :

  1. Chemin des secrets : GitHub Secrets → Paramètres Bicep → Key Vault → Références Key Vault dans App Configuration → Code
  2. Chemin de config 1 : Paramètres Bicep → App Configuration Store → Code
  3. Chemin de config 2 : Paramètres directs du Function App (Bicep : amorçage uniquement) → Variables d'environnement → Pattern Options
  4. Chemin dev local : local.settings.json → IConfiguration → Pattern Options

1.1 Nethris:BaseUrl¶

Classification : Configuration (non sensible)

Paramètre Bicep GitHub (main.bicep)
  ├─ Défaut : 'https://clients.nethris.com/CSPaySuiteServices/wsWebSuiteService.svc/V.1.00'
  │
  ├─ infra/parameters/{env}.bicepparam
  │  └─ dev/test/prod : même valeur par défaut
  │
  ├─ Flux de déploiement Bicep (infra/modules/functionApp.bicep & appConfiguration.bicep)
  │  └─ Paramètre AppConfig :  'Nethris:BaseUrl' = valeur du paramètre (aucun paramètre direct du Function App)
  │
  ├─ Résolution à l'exécution
  │  ├─ Le Function App lit via App Configuration (chargée au démarrage par AddAzureAppConfiguration)
  │  ├─ Liaison IConfiguration : configuration["Nethris:BaseUrl"]
  │  └─ Pattern Options : NethrisOptions.BaseUrl (depuis AppConfig)
  │
  └─ Consommation dans le code
     └─ Constructeur NethrisAuthClient : Définit HttpClient.BaseAddress
         └─ BaseUrl.TrimEnd('/') + "/" → point de terminaison pour tous les appels Nethris API

Développement local : local.settings.json → Values.Nethris:BaseUrl
Cohérence des noms de propriétés :

  • Paramètres Bicep : nethrisBaseUrl
  • Paramètres Function App : Nethris__BaseUrl (style variable d'env Azure)
  • AppConfiguration : Nethris:BaseUrl (style section options)
  • Classe Options : NethrisOptions.BaseUrl (propriété POCO)

1.5 Nethris:UserPassword¶

Classification : 🔴 Secret (hautement sensible)

FLUX A : GitHub Actions → Key Vault → App Configuration (déploiement Prod/Test)
═══════════════════════════════════════════════════════════════════════════════

  Secret d'organisation GitHub
  ├─ Nom du secret : NETHRIS_USER_PASSWORD
  └─ Valeur : (chiffrée dans GitHub)
      │
      ├─ Déclencheur CI/CD : workflow infra-deploy.yml
      │  └─ Étape : "Deploy infrastructure"
      │     └─ Commande : az deployment group create
      │        └─ Paramètre : --parameters nethrisUserPasswordValue="${{ secrets.NETHRIS_USER_PASSWORD }}"
      │
      ├─ Traitement Bicep (main.bicep)
      │  ├─ Paramètre : @secure() param nethrisUserPasswordValue string = ''
      │  │
      │  └─ Module : keyVault (keyVault.bicep)
      │     └─ Condition : if (shouldProvisionNethrisUserPassword)
      │        ├─ Évalue : !empty(nethrisUserPasswordValue) && !contains(toLower(value), 'placeholder')
      │        │
      │        └─ Crée un secret Azure Key Vault
      │           ├─ Nom du coffre : ${prefix}-${env}-kv-${uniqueString}
      │           ├─ Nom du secret : 'nethris-user-password'
      │           └─ Valeur du secret : (chiffrée dans Key Vault)
      │
      └─ Azure Key Vault
         ├─ URI : https://{keyVaultName}.vault.azure.net/
         ├─ URI du secret : {keyVaultUri}/secrets/nethris-user-password/
         │
         ├─ Accès RBAC
         │  ├─ Rôle : Key Vault Secrets User (4633458b-17de-408a-b874-0445c86b69e6)
         │  └─ Principal : identité managée du Function App
         │
         └─ → Le Function App lit via DefaultAzureCredential + identité managée
            │
            ├─ App Configuration (appConfiguration.bicep)
            │  ├─ ConfigStore : ${prefix}-${environment}-appconfig-${uniqueString}
            │  ├─ Clé : 'Nethris:UserPassword'
            │  ├─ Content Type : 'application/vnd.microsoft.appconfig.keyvaultref+json;charset=utf-8'
            │  └─ Valeur (JSON) : {"uri":"https://{keyVaultUri}secrets/nethris-user-password/"}
            │
            └─ FunctionAppStartup.ConfigureAppConfiguration()
               └─ AddAzureAppConfiguration(options =>
                  ├─ Connexion au point de terminaison App Configuration
                  ├─ ConfigureKeyVault(keyVault => keyVault.SetCredential(credential))
                  └─ Résout l'URI du secret → récupère la valeur réelle depuis Key Vault


FLUX B : Développement local (local.settings.json, NON CHIFFRÉ POUR DEV UNIQUEMENT)
═════════════════════════════════════════════════════════════════════════════

  local.settings.json (DEV UNIQUEMENT — .gitignored)
  ├─ IsEncrypted : false
  ├─ Clé : Nethris:UserPassword
  └─ Valeur : (identifiant dev/sandbox)
      │
      └─ Exécution : l'hôte Azure Functions charge directement dans IConfiguration

  │
  └─ Liaison de propriété

        └─ En dev : Résolu depuis local.settings.json


CONSOMMATION DANS LE CODE
═════════════════

  NethrisAuthClient(HttpClient, IOptions<NethrisOptions>, ILogger)
  ├─ Constructeur : _options = options.Value
  │
  └─ LoginAsync()
     └─ Sérialisation JSON :
        ├─ userPassword = _options.UserPassword
        │
        └─ Journalisation : le journal « Authenticating to Nethris API » n'inclut que AppID et UserCode (aucun masque de

⚠️ NOTES DE SÉCURITÉ :

  • Jamais versionné dans Git — local.settings.json est dans le .gitignore

  • Validation : Champ requis ([Required]) — le déploiement échoue s'il est manquant
  • Contrôle d'accès : Seule l'identité managée du Function App peut lire depuis Key Vault

3.1 Ledger:TableServiceUri¶

Classification : Configuration (semi-sensible — identifiant d'infrastructure)

CALCULÉ PAR MAIN.BICEP (pas un paramètre direct)
════════════════════════════════════════════════

  main.bicep → storage.bicep
  ├─ Génère : Nom du compte de stockage
  │  └─ Patron : ${prefix}${environment}st${uniqueString()} (p. ex. eqldevstXXXXXXXX)
  │
  ├─ Sortie du module storage : storageAccountName
  │
  └─ main.bicep calcule :
     └─ tableServiceUri = 'https://${storage.outputs.name}.table.${az.environment().suffixes.storage}/'


Flux de déploiement Bicep
═════════════════════

  main.bicep → appConfiguration.bicep
  ├─ Paramètre : tableServiceUri (calculé par main.bicep)
  │  (aucun paramètre direct 'Ledger__TableServiceUri' sur le Function App)
  │
  └─ appConfiguration.bicep
     ├─ Paramètre AppConfig : 'Ledger:TableServiceUri'
     └─ Content-Type : 'text/plain'


Résolution à l'exécution
