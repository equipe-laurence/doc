Guide de développement local¶

Ce guide explique comment remplir local.settings.json pour le développement et les tests en local.

Prérequis¶

  • Azure Functions Core Tools v4
  • Azurite (émulateur de stockage local) ou un compte de stockage Azure
  • Accès à un compte sandbox Nethris
  • Azure CLI ou l'extension Azure pour VS Code (pour s'authentifier avec DefaultAzureCredential en local)

Configuration de local.settings.json¶

local.settings.json est ignoré par Git et n'est jamais versionné. Copiez le fichier modèle versionné et remplissez vos valeurs :

cp src/EquipeLaurence.Functions/local.settings.template.json \
   src/EquipeLaurence.Functions/local.settings.json

Le modèle se trouve dans src/EquipeLaurence.Functions/local.settings.template.json. Toutes les valeurs entre <…> sont à remplacer.

Identifiants du sandbox Nethris¶

Contactez votre administrateur Nethris pour obtenir :

Champ Description
Nethris:AppId Identifiant d'application (fourni par Nethris pour les API personnalisées)
Nethris:BusinessCode Code d'entreprise de votre compagnie
Nethris:UserCode Code d'utilisateur de service (créé dans l'administration Nethris)
Nethris:UserPassword Mot de passe de l'utilisateur de service

L'utilisateur de service doit être de type Utilisateur de services et doit être autorisé pour l'application API.

Identifiants de la bibliothèque de documents SharePoint¶

Pour trouver le SiteId et le DriveId de votre site SharePoint de développement :

# Obtenir l'identifiant du site
az rest --method GET \
  --url "https://graph.microsoft.com/v1.0/sites/<votre-tenant>.sharepoint.com:/sites/<votre-site>" \
  --query "id"

# Obtenir l'identifiant du lecteur (bibliothèque de documents)
az rest --method GET \
  --url "https://graph.microsoft.com/v1.0/sites/<site-id>/drives" \
  --query "value[?name=='Documents'].id | [0]"

Mode d'authentification Graph API (SharePoint:AuthMode)¶

Le Function App supporte deux modes d'authentification pour l'API Microsoft Graph (SharePoint) :

Valeur Credential utilisé Quand l'utiliser
ClientSecret (défaut) ClientSecretCredential Développement local, CI/CD pipelines
ManagedIdentity ManagedIdentityCredential Déploiement sur Azure avec identité managée

Mode ClientSecret (défaut) — Variables d'environnement requises :

Variable Description
AZURE_TENANT_ID Identifiant du locataire Entra ID (UUID)
AZURE_CLIENT_ID Identifiant de l'application (App Registration)
AZURE_CLIENT_SECRET Secret client de l'application (valeur, pas l'ID)

⚠️ AzureAd:ClientSecret est réservé à Easy Auth — ne pas l'utiliser ici.

Mode ManagedIdentity — Aucune variable requise. L'identité managée du Function App est utilisée automatiquement. Voir la section Permission Graph Sites.Selected pour la configuration Azure.

Exemple de configuration locale (local.settings.json) pour le mode ClientSecret :

{
  "SharePoint:SiteId": "<site-id>",
  "SharePoint:DriveId": "<drive-id>",
  "SharePoint:AuthMode": "ClientSecret",
  "AZURE_TENANT_ID": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "AZURE_CLIENT_ID": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "AZURE_CLIENT_SECRET": "<secret-value>"
}

Exemple de configuration Azure (App Settings) pour le mode ManagedIdentity :

{
  "SharePoint:SiteId": "<site-id>",
  "SharePoint:DriveId": "<drive-id>",
  "SharePoint:AuthMode": "ManagedIdentity"
}

Registre de synchronisation (Ledger)¶

Le registre utilise Azure Table Storage pour suivre les rapports déjà synchronisés.

Champ Description
Ledger:TableServiceUri URI du service Azure Table Storage (ex. https://<compte>.table.core.windows.net/)
Ledger:TableName Nom de la table utilisée pour le suivi (par défaut : SyncLedger)

Pour les tests locaux, vous pouvez utiliser Azurite ou un compte de stockage Azure personnel.

Option A : Azurite (recommandé pour le développement hors ligne)

Azurite ne supporte pas encore l'URI du point de terminaison Table Storage de la même manière qu'Azure. Utilisez plutôt la chaîne de connexion de l'émulateur Azure.Data.Tables. Il se peut que vous deviez ajuster Program.cs localement pour utiliser une chaîne de connexion en développement. Consultez la documentation Azurite.

Option B : Compte de stockage Azure

Ledger:TableServiceUri = https://<votre-compte-de-stockage>.table.core.windows.net/
Ledger:TableName = SyncLedger

Authentifiez-vous localement avec :

az login

DefaultAzureCredential utilisera automatiquement vos identifiants az login.

SMS / Twilio avec authentification Entra ID¶

La fonctionnalité SMS est désactivée par défaut. Pour l'activer en local, configurez le fournisseur Twilio et les paramètres Entra ID.

Champ Description
Sms:Enabled Bascule explicite (true/false). Par défaut : false
Sms:Provider Fournisseur SMS : twilio ou disabled. Par défaut : disabled
Twilio:AccountSid Identifiant du compte Twilio
Twilio:AuthToken Token d'authentification Twilio (secret à protéger)
Twilio:FromNumber Numéro d'expédition Twilio (format E.164, ex. +15551234567)

L'envoi de SMS via POST /api/notifications/sms/send-by-bureau nécessite également un jeton Entra ID Bearer valide. Configurez les paramètres suivants pour la validation des jetons :

Champ Description
AzureAd:TenantId Identifiant du locataire Entra ID (UUID)
AzureAd:ClientId Identifiant de l'application enregistrée dans Entra ID
AzureAd:Audience Audience du jeton (par défaut : api://{ClientId})
AzureAd:AuthorizedGroupId Object ID du groupe Entra ID autorisé (UUID, optionnel)

Exemple de configuration locale (local.settings.json) :

{
  "Sms:Enabled": "true",
  "Sms:Provider": "twilio",
  "Twilio:AccountSid": "ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "Twilio:AuthToken": "your-twilio-auth-token",
  "Twilio:FromNumber": "+15551234567",
  "AzureAd:TenantId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "AzureAd:ClientId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "AzureAd:Audience": "api://xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "AzureAd:AuthorizedGroupId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
}

Pour tester localement :

# Récupérer un token Entra ID via Azure CLI
BEARER_TOKEN=$(az account get-access-token --resource api://votre-client-id --query accessToken -o tsv)

# Appeler le formulaire SMS
curl -X GET "http://localhost:7071/api/notifications/sms/form" \
  -H "Authorization: Bearer $BEARER_TOKEN"

# Envoyer un SMS de test
curl -X POST "http://localhost:7071/api/notifications/sms/send-by-bureau" \
  -H "Authorization: Bearer $BEARER_TOKEN" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "locationCode=MTL&messageBody=Test+SMS"

Remarques : - Les paramètres Twilio et Entra ID doivent provenir d'Azure Key Vault en production - En local, placez-les directement dans local.settings.json - L'authentification Entra ID ([Authorize]) est toujours requise, indépendamment de la présence de AzureAd:AuthorizedGroupId (cette clé ne pilotait qu'un contrôle de groupe optionnel, désormais retiré — voir .squad/decisions.md) - Voir AadAuthOptions.cs pour la structure complète de configuration

Contourner l'authentification en local (développement uniquement) :

Pour tester les endpoints SMS sans obtenir de jeton Entra ID, ajoutez la clé suivante à local.settings.json :

{
  "Sms:BypassAuthInDevelopment": "true"
}

Ce contournement est doublement verrouillé par mesure de sécurité — il ne s'active que si les deux conditions suivantes sont vraies : 1. L'hôte s'exécute avec IHostEnvironment.IsDevelopment() == true (c'est le cas par défaut avec func start en local, jamais dans un environnement déployé dev/test/prod App Service) 2. Sms:BypassAuthInDevelopment est explicitement à true

Un avertissement (LogWarning) est écrit dans les journaux à chaque requête où le contournement est utilisé, pour qu'il reste visible qu'il est actif. Ne provisionnez jamais cette clé dans Azure App Configuration ou Key Vault.

Permission Graph Sites.Selected (consentement administrateur requis)¶

Le Function App utilise la permission Microsoft Graph Sites.Selected pour écrire des fichiers dans une bibliothèque SharePoint spécifique. Cette permission ne peut pas être accordée via le consentement OAuth standard — elle nécessite qu'un administrateur limite explicitement la permission au site cible après le déploiement.

Étape post-déploiement pour l'administrateur (exécuter une fois par environnement) :

# Requiert le module PnP PowerShell
Connect-PnPOnline -Url "https://<tenant>.sharepoint.com/sites/<site>" -Interactive

Grant-PnPAzureADAppSitePermission `
  -AppId "<app-id-identite-managee-function-app>" `
  -DisplayName "EquipeLaurence Function App" `
  -Site "https://<tenant>.sharepoint.com/sites/<site>" `
  -Permissions Write

Ou via l'API REST Microsoft Graph :

az rest --method POST \
  --url "https://graph.microsoft.com/v1.0/sites/<site-id>/permissions" \
  --body '{
    "roles": ["write"],
    "grantedToIdentities": [{
      "application": {
        "id": "<client-id-identite-managee>",
        "displayName": "EquipeLaurence Function App"
      }
    }]
  }'

L'identifiant client de l'identité managée est produit par le déploiement Bicep sous functionApp.outputs.principalId.

Exécution en local¶

cd src/EquipeLaurence.Functions
func start

Points de terminaison disponibles¶

Une fois le Function App démarré, les points de terminaison suivants sont disponibles :

Synchronisation Nethris¶

Méthode Route Fonction Auth Description
GET /api/sync/nethris-reports NethrisReportSync Function Key Déclenche une synchronisation manuelle 
curl -X GET "http://localhost:7071/api/sync/nethris-reports?code=<function-key>"

SMS (requiert Sms:Enabled = true et configuration Entra ID)¶

Méthode Route Fonction Auth Description
GET /api/notifications/sms/form SmsFormFunction Entra ID (Bearer) Affiche le formulaire HTML pour sélectionner un bureau
POST /api/notifications/sms/send-by-bureau SendSmsByBureauFunction Entra ID (Bearer) Envoie un SMS d'urgence aux destinataires du bureau sélectionné
POST /api/sms/inbound TwilioInboundSms Event Grid Reçoit les SMS entrants relayés par Twilio
POST /api/sms/delivery-status TwilioDeliveryStatus Event Grid Reçoit les statuts de livraison SMS relayés par Twilio 
# Récupérer un token Entra ID
TOKEN=$(az account get-access-token --resource api://votre-client-id --query accessToken -o tsv)

# Accéder au formulaire SMS
curl -X GET "http://localhost:7071/api/notifications/sms/form" \
  -H "Authorization: Bearer $TOKEN"

# Envoyer un SMS (nécessite un token Bearer Entra ID)
curl -X POST "http://localhost:7071/api/notifications/sms/send-by-bureau" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "locationCode=MTL&messageBody=Test+SMS"
