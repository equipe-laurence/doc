Publication de la documentation¶

Ce guide explique comment la documentation est construite et publiée automatiquement sur GitHub Pages à chaque merge sur main, ainsi que les étapes de configuration initiale à effectuer une seule fois.

Architecture de publication¶

equipe-laurence/integration-nethris          equipe-laurence/doc
─────────────────────────────────           ──────────────────────
  docs/                                       branche gh-pages
  zensical.toml                    ──────►      index.html
  .github/workflows/                           assets/
    deploy-docs.yml                            ...
Élément Valeur
Outil de génération Zensical (zensical build)
Fichier de configuration zensical.toml (racine du dépôt)
Dossier source docs/
Dossier de build (local) site/docs/
Dépôt de publication equipe-laurence/doc
Branche de publication gh-pages
URL publique https://equipe-laurence.github.io/doc/

Pipeline GitHub Actions (deploy-docs.yml)¶

Le workflow .github/workflows/deploy-docs.yml se déclenche :

  • Automatiquement à chaque push sur la branche main
  • Manuellement via Actions → Déployer la documentation → Run workflow

Étapes du pipeline¶

1. Checkout du code source (integration-nethris)
2. Installation de Python 3.x
3. pip install -r requirements.txt   → installe zensical
4. zensical build                    → génère site/docs/
5. peaceiris/actions-gh-pages@v4     → pousse site/docs/ vers
                                       equipe-laurence/doc@gh-pages

Configuration initiale (à faire une seule fois)¶

1. Créer le Personal Access Token (DOCS_DEPLOY_TOKEN)¶

Le pipeline pousse vers un dépôt externe (equipe-laurence/doc), ce qui nécessite un PAT — le GITHUB_TOKEN par défaut n'a pas accès aux dépôts tiers.

  1. Connecte-toi avec le compte qui a accès en écriture à equipe-laurence/doc
  2. Va dans Settings → Developer settings → Personal access tokens → Fine-grained tokens (ou Classic)
  3. Crée un token avec les permissions suivantes :
  4. Repository access : equipe-laurence/doc uniquement
  5. Permissions : Contents → Read and write
  6. Copie le token généré

!!! warning "Sécurité" Ne partage jamais ce token et ne le commite pas dans le dépôt.

2. Ajouter le secret dans le dépôt source¶

  1. Va dans equipe-laurence/integration-nethris → Settings → Secrets and variables → Actions
  2. Clique New repository secret
  3. Name : DOCS_DEPLOY_TOKEN
  4. Secret : colle le token créé à l'étape précédente
  5. Clique Add secret

3. Vérifier que le dépôt equipe-laurence/doc existe¶

Le dépôt equipe-laurence/doc doit être public (ou accessible à GitHub Pages). Il n'a pas besoin de contenu initial — le pipeline crée la branche gh-pages lors du premier déploiement.

4. Activer GitHub Pages sur equipe-laurence/doc¶

Cette étape n'est requise qu'une seule fois, après le premier déploiement réussi du pipeline.

  1. Va dans equipe-laurence/doc → Settings → Pages
  2. Source → Deploy from a branch
  3. Branch → gh-pages / / (root)
  4. Clique Save
  5. Attends ~2 minutes — l'URL https://equipe-laurence.github.io/doc/ devient accessible

Mettre à jour la documentation en local¶

Pour prévisualiser la doc localement avant de pousser :

# Windows — utilise le script inclus
.\démarre-documentation.cmd

Le script installe automatiquement les dépendances dans un virtualenv et lance zensical serve sur http://localhost:8000.

Dépannage¶

Symptôme Cause probable Solution
Pipeline échoue (403/404) DOCS_DEPLOY_TOKEN manquant ou expiré Recréer le secret (voir §1 et §2)
URL retourne 404 après déploiement GitHub Pages pas encore activé Activer Pages sur equipe-laurence/doc (voir §4)
Assets manquants (CSS/JS) site_url incorrect dans zensical.toml Vérifier que site_url = "https://equipe-laurence.github.io/doc/"
Build échoue localement Dépendances manquantes Relancer démarre-documentation.cmd pour réinstaller
