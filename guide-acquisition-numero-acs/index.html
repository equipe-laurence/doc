Guide d'acquisition d'un numéro de téléphone — Azure Communication Services¶

Ce guide couvre l'acquisition complète d'un numéro sans-frais (toll-free) pour l'envoi de SMS via Azure Communication Services (ACS) depuis une ressource en région Canada East.

Audience : Administrateurs Azure, responsables RH, responsable vie privée
Durée totale : 2–6 semaines (selon scenario réglementaire)

Vue d'ensemble¶

L'acquisition d'un numéro SMS dans Azure Communication Services suit ces étapes clés :

  1. Prérequis — Vérifier la ressource ACS et préparer le dossier documentaire
  2. Type de numéro — Choisir toll-free (SMS recommandé au Canada)
  3. Acquisition du portail — Obtenir le numéro en 5 minutes
  4. Vérification toll-free — Soumettre le formulaire de conformité (obligatoire depuis nov. 2023)
  5. Conformité réglementaire — Respecter CASL, Loi 25, CRTC
  6. Configuration technique — Intégrer le numéro avec Key Vault et webhooks
  7. Plan d'action — Étapes de déploiement et d'approbation

Pour le contexte réglementaire complet, consultez Conformité SMS.

Étape 1 — Prérequis¶

✅ Abonnement et ressource Azure¶

  • Abonnement Azure actif — Les comptes d'essai (trial) ne supportent pas l'acquisition de numéros SMS. Utilisez un abonnement payant.
  • Ressource Azure Communication Services — Créée en région Canada East (Quebec City). ACS supporte SMS dans Canada Central (Toronto) et Canada East; Canada East est recommandé pour les données québécoises.
  • Rôle d'accès — Vous disposez d'un rôle Contributor ou Owner sur la ressource ACS.

Vérifier votre ressource :

az communication show --name <resource-name> --resource-group <rg> --query "location"
# Doit afficher : canadaeast

📋 Documents à préparer (checklist)¶

Avant de commencer le processus de portail, rassemblez ces documents. Ils seront requis lors de la soumission du formulaire de vérification toll-free.

  • Raison sociale complète — Nom officiel de votre organisation (ex. : Équipe Laurence Inc.)
  • Adresse commerciale officielle — Adresse physique complète (rue, ville, province, code postal) — en Canada
  • Coordonnées du responsable — Nom complet, titre, adresse courriel professionnelle, numéro de téléphone
  • Description du cas d'usage — Résumé de votre utilisation (ex. : Notifications d'urgence et de sécurité aux employés)
  • Volume estimé mensuel — Nombre approximatif de SMS par mois (ex. : 100–500 ou 2000)
  • 2–3 exemples de messages types — Snippets de messages réels que vous enverrez (accents français acceptés)
  • Preuve du mécanisme d'opt-out — Capture d'écran ou document montrant comment les utilisateurs se désinscrire (STOP/ARRET)
  • Clause de consentement — Copie du libellé utilisé dans votre contrat d'emploi ou manuel des employés mentionnant les SMS

Étape 2 — Type de numéro (Toll-Free)¶

❓ Pourquoi sans-frais?¶

Au Canada, les options pour l'envoi de SMS via Azure Communication Services sont limitées :

Type SMS via ACS Délai Recommandation
Toll-Free (1-8XX-XXXX-XXXX) ✅ Oui 1–15 jours ✅ Recommandé
Long Code local (10 chiffres) ❌ Non (voix seulement) — ❌ Ne supporte pas SMS
Short Code (5–6 chiffres) ✅ Oui (via CWTA) 4–12 semaines ⚠️ Non applicable ici
Alphanumeric Sender ID ❌ Non au Canada — ❌ Non disponible

Conclusion : Les numéros sans-frais sont la seule option viable pour envoyer du SMS via ACS au Canada. Un numéro local (long code) n'accepte que la voix, pas le SMS.

💰 Tarification (Canada)¶

Élément Coût
Numéro sans-frais (locationaires) $2.00 CAD/mois
SMS sortant $0.0085 CAD par segment*
SMS entrant Non disponible au Canada

*Un segment = 160 caractères (GSM-7). Les accents français utilisent UCS-2 et réduisent à 70 caractères par SMS.

Exemple de coûts mensuels :

  • 1 numéro sans-frais + 500 SMS (150 segments) = $2.00 + $1.28 = ~$3.28 CAD/mois
  • 1 numéro sans-frais + 5 000 SMS (1 500 segments) = $2.00 + $12.75 = ~$14.75 CAD/mois

Étape 3 — Acquisition du numéro dans le portail Azure¶

1. Naviguer vers la ressource ACS¶

  1. Accédez au portail Azure
  2. Cherchez votre Communication Services resource (groupe de ressources cible)
  3. Cliquez sur la ressource ACS pour ouvrir le tableau de bord
  4. Dans le menu de gauche, sélectionnez Phone numbers (ou Numéros de téléphone)

2. Lancer l'acquisition¶

  1. Cliquez sur le bouton + Get (ou + Obtenir)
  2. Une fenêtre de configuration s'ouvre avec le formulaire d'acquisition

3. Sélectionner les options¶

Remplissez le formulaire avec ces valeurs :

Champ Valeur
Country/Region Canada 🍁
Phone number type Toll-Free
SMS capability Send and receive ✅
Quantity 1 (pour commencer)

Cliquez sur Search pour afficher les numéros disponibles.

4. Confirmer et acquérir¶

  1. Sélectionnez un numéro sans-frais dans la liste (ex. : +1-833-123-4567)
  2. Cliquez sur Next ou Continue
  3. L'écran de confirmation affiche :
  4. Le numéro acquis
  5. Le coût mensuel ($2.00 CAD)
  6. Les capacités (SMS send/receive)
  7. Cliquez sur Acquire pour finaliser

!!! note "Acquisition instantanée" Le numéro est acquis dans votre ressource ACS immédiatement (moins de 5 minutes). Cependant, il n'est pas utilisable pour l'envoi de SMS jusqu'à la vérification toll-free (Étape 4).

5. Vérifier l'acquisition¶

Retournez à l'onglet Phone numbers de votre ressource ACS. Vous devriez voir votre numéro dans la liste avec le statut Unverified (non vérifié).

Toll-Free: +1-833-123-4567
  Status: Unverified 🔴
  Capabilities: SMS (send/receive)
  Monthly cost: $2.00 CAD

Étape 4 — Vérification Toll-Free (obligatoire)¶

!!! warning "⚠️ ÉTAPE OBLIGATOIRE DEPUIS LE 8 NOVEMBRE 2023" Les transporteurs canadiens bloquent tous les SMS en provenance de numéros sans-frais non vérifiés. La vérification n'est pas optionnelle.

📝 Accéder au formulaire de vérification¶

  1. Dans votre ressource ACS, allez à Phone numbers → sélectionnez votre numéro
  2. Cliquez sur l'onglet Regulatory documents (ou Documents réglementaires)
  3. Sélectionnez Toll-Free Verification Form dans la liste
  4. Cliquez sur Apply ou + Add

📋 Remplir le formulaire¶

Le formulaire comprend plusieurs sections. Remplissez chaque champ avec les informations préparées à l'étape 1 :

Section Champs Détails
Business Info Raison sociale Nom légal de votre organisation
Adresse commerciale Adresse physique complète (Canada uniquement)
Type d'entreprise Sélectionnez le plus proche (ex. : Business ou Non-profit)
Contact Person Nom complet Personne responsable du numéro
Titre/fonction Rôle (ex. : HR Manager, IT Director)
Courriel professionnel Adresse courriel d'accès continu
Numéro de téléphone Numéro professionnel (peut être différent du numéro SMS)
Use Case Description détaillée Résumé de votre utilisation (ex. : Emergency notifications to employees)
Volume mensuel estimé Nombre approximatif (ex. : 500 SMS/month)
Message Samples 2–3 exemples Copier/coller des vrais messages que vous enverrez
Consentement Cochez la case confirmant que vous avez le consentement explicite
Opt-Out Mécanisme STOP/ARRET Décrivez comment les utilisateurs peuvent se désinscrire

✅ Soumettre¶

  1. Relisez tous les champs pour les erreurs ou omissions
  2. Cochez la case d'engagement légal (si présente)
  3. Cliquez sur Submit ou Envoyer

!!! tip "Conseil : Approbation plus rapide" Fournissez des exemples de messages clairs et courts. Les applications incomplètes ou vagues rallongent le processus.

⏱️ Délai de traitement¶

Une fois le formulaire soumis, le statut du numéro passe à Verification Pending (vérification en cours).

Scénario Délai
Cas optimal 1–2 jours ouvrables
Cas standard 5–10 jours ouvrables
Cas complexe (information manquante) Jusqu'à 15 jours ouvrables
Rejet + resoumission +5–10 jours supplémentaires

Microsoft vous informera par courriel à l'adresse du responsable une fois la vérification terminée. Le statut passe à Verified (vérifié) 🟢 lorsqu'il est approuvé.

!!! note "Pas de rejet = pas de SMS" Si vous tentez d'envoyer un SMS avec un numéro non vérifié, votre message sera bloqué en amont par le transporteur. Attendez la vérification avant les tests.

Étape 5 — Conformité réglementaire¶

📜 CASL — Loi canadienne anti-pourriel¶

La Loi canadienne anti-pourriel (CASL) encadre tous les messages électroniques commerciaux au Canada, y compris les SMS.

!!! tip "✅ Bonne nouvelle : Exemption pour SMS d'urgence" Les SMS d'urgence et de sécurité aux employés sont exemptés du consentement préalable si : - L'employé est en relation d'emploi actuelle - Le SMS concerne un risque de sécurité ou une urgence - Le message n'est pas promotionnel

Checklist CASL :

  • Documenter la relation d'emploi — Conservez les registres d'embauche et les dossiers RH pour justifier la relation d'emploi.
  • Implémenter le mécanisme STOP/ARRET — Tous les SMS sortants doivent permettre la désinscription immédiate en répondant STOP ou ARRET.
  • Conserver les registres d'opt-out — Maintenez un registre des employés qui se désincrivent (voir Conformité SMS — Désinscription pour la table SmsOptOut).
  • Identification de l'expéditeur — Le SMS doit clairement identifier votre organisation (ex. : [Emergency Alert - Équipe Laurence]).
  • Auditer les consentements — Conservez des preuves (contrats, manuels) que les employés consentent au SMS lors de l'embauche.

🛡️ Loi 25 (Québec) — EFVP obligatoire¶

La Loi 25 — Loi sur la protection des renseignements personnels du Québec est la loi de confidentialité la plus stricte au Canada.

!!! warning "⚠️ ACTION OBLIGATOIRE : EFVP avant déploiement" Vous devez compléter une Étude de faisabilité et d'impact sur la vie privée (EFVP) AVANT de déployer votre système SMS. L'EFVP documente les risques de confidentialité liés aux données qui transiteront par l'infrastructure Microsoft (notamment les serveurs US).

Responsabilités :

  • Mandater le responsable vie privée — Nommez une personne (généralement un DPO ou responsable RH) pour mener l'EFVP.
  • Documenter le flux de données — Décrivez comment les numéros de cellulaire et les messages transitent via ACS vers les serveurs Microsoft (Canada East region, mais traitement possible aux É-U).
  • Analyser les risques transfrontaliers — Les serveurs de Microsoft incluent des installations aux É-U; documentez les garanties contractuelles (Microsoft Cloud Agreement) et les limitations de confidentialité.
  • Rétention des données — Définissez une politique de rétention (minimum 2 ans pour les journaux d'audit conformément à la Loi 25).
  • Obtenir l'approbation — L'EFVP doit être approuvée par la direction avant le déploiement en production.

Pour plus de détails, consultez la Politique de conformité Loi 25.

📞 CRTC — Autorités de régulation canadiennes¶

Le Conseil de la radiodiffusion et des télécommunications canadiennes (CRTC) régule les SMS au Canada.

Obligations CRTC :

  • Vérification toll-free — Complètement conforme via le formulaire ACS (couvre les exigences CRTC).
  • STOP/ARRET keywords — Vous devez honorer les demandes d'opt-out immédiatement. Une réponse lente viole la réglementation CRTC.
  • No unsolicited SMS — Aucun SMS non sollicité (marketing, publicité) aux employés. Les notifications de sécurité sont autorisées.
  • Identity and routing — Le numéro sans-frais affiche correctement votre organisation (pas d'usurpation d'identité).

!!! note "Implémentation : Webhooks Event Grid" ACS ne supprime pas automatiquement les destinataires qui envoient STOP (contrairement à Twilio). Vous devez implémenter une fonction Azure qui écoute les messages entrants (Event Grid) et met à jour la table SmsOptOut. Voir Guide d'intégration API SMS — Inbound SMS.

Étape 6 — Configuration technique post-acquisition¶

🔐 Connexion String et Key Vault¶

Une fois votre numéro vérifié, intégrez-le dans votre architecture.

Où stocker la connexion :

  1. Dans votre Key Vault (ex. : eql-kv-prod), créez un secret :
  2. Name: acs-connection-string

  3. Value: Copiez la chaîne de connexion depuis votre ressource ACS (portail → Keys → Connection String)

  4. Dans App Configuration (ex. : eql-appconfig-prod), créez une clé :

  5. Key: Acs:ConnectionString
  6. Content Type: application/vnd.microsoft.appconfig.keyvaultref+json;charset=utf-8

  7. Value: 

    { "uri": "https://<your-keyvault>.vault.azure.net/secrets/acs-connection-string/" }

  8. Référencez cette clé dans votre code C# : 

    var connectionString = configuration["Acs:ConnectionString"];
var smsClient = new SmsClient(new Uri(connectionString));

Pour les étapes détaillées, consultez Guide de configuration du fournisseur SMS.

🪝 Webhook entrant pour opt-out (Event Grid)¶

Pour gérer les réponses STOP/ARRET, configurez un webhook :

  1. Créer une fonction Azure pour recevoir les SMS entrants
  2. Endpoint: POST /api/sms/inbound/acs

  3. Trigger: Event Grid (Microsoft.Communication.IncomingSMSReceived)

  4. Écouter les mots-clés : STOP, STOPALL, UNSUBSCRIBE, CANCEL, END, QUIT, ARRET (français)

  5. Mettre à jour la table SmsOptOut avec le numéro qui s'est désinscrit

  6. Retourner TwiML vide (200 text/xml) pour confirmer la réception

Pour la configuration complète, consultez Guide d'intégration API SMS — Gestion des STOP/ARRET.

Étape 7 — Plan d'action¶

Semaine 1 — Actions immédiates¶

Objectif : Amorcer le processus réglementaire et acquérir le numéro.

  • Mandater responsable vie privée — Nommez le responsable qui mènera l'EFVP
  • Préparer le dossier documentaire — Rassemblez tous les documents (section 1)
  • Vérifier la ressource ACS — Confirmez la région Canada East, l'accès Contributor
  • Acquérir le numéro toll-free — Complétez le portail (Étape 3 — 5 min)
  • Soumettre la vérification toll-free — Remplissez et soumettez le formulaire (Étape 4 — 30 min)
  • Informer la direction — Notification que le processus a commencé (EFVP + vérification en attente)

Durée: ~2 heures de travail

Semaines 2–3 — Conformité réglementaire¶

Objectif : Obtenir l'approbation réglementaire et finaliser la conformité.

  • Mentalité EFVP — Le responsable vie privée amorce l'Étude de faisabilité et d'impact
  • Documenter le consentement SMS — Ajoutez une clause dans le contrat d'emploi ou le manuel RH
  • Préparer le mécanisme opt-out — Concevoir le flux pour honorer STOP/ARRET
  • Vérification toll-free approuvée? — Vérifiez votre courriel; le numéro doit passer à Verified 🟢
  • Revue CASL — Documentez pourquoi les SMS d'urgence sont exemptés

Durée: 2–3 jours ouvrables (principalement en attente de la vérification Microsoft)

Semaines 4–5 — Développement technique¶

Objectif : Intégrer le numéro ACS dans le système et mettre en place les mécanismes de conformité.

  • Stockage de la connexion — Copier la chaîne de connexion vers Key Vault + App Configuration
  • Implémenter le webhook inbound — Créer la fonction Event Grid pour capturer les STOP/ARRET
  • Table SmsOptOut — Déployer/mettre à jour la table Azure Storage pour les désinscriptions
  • Table SmsAuditLog — Implémenter l'audit (rétention 2 ans minimum)
  • Réponse automatique bilingue — Test avec ARRET (français) + STOP (anglais)
  • Tests unitaires — Vérifier la logique opt-out et la désinscription

Durée: ~15 heures de développement

Semaines 5–6 — Validation et déploiement¶

Objectif : Tester complètement le système et le déployer en production.

  • EFVP approuvée — Confirmation que l'Étude de faisabilité et d'impact est terminée et approuvée
  • Test end-to-end opt-out — Envoyer un SMS test; répondre STOP, vérifier la désinscription
  • Test bilingue — Envoyer avec ARRET (français); vérifier que la désinscription fonctionne
  • Validation piste d'audit — Vérifier que SmsAuditLog enregistre chaque tentative
  • Revue sécurité — Audit final avant production (secrets en Key Vault, pas de hardcoding)
  • Communication aux employés — Informer les employés que le SMS est désormais actif (procédure opt-out)
  • Déploiement production — Passer le switch Sms:Provider de "Disabled" à "Acs" dans App Configuration

Durée: 1–2 semaines (principalement attente d'approbations)

Semaines 7+ — Exploitation¶

Objectif : Surveiller et maintenir le système en production.

  • Surveillance des erreurs — Surveiller le taux d'échec des SMS dans Application Insights
  • Gestion des opt-out — Traiter les demandes d'opt-out manuelles (si nécessaire)
  • Rapport mensuel — Documenter le volume de SMS, les taux de désinscription, les coûts
  • Conformité continue — Audit annuel de l'EFVP et des consentements

Questions fréquentes¶

Q: Puis-je utiliser un numéro local (long code) pour le SMS?¶

R: Non. Les numéros locaux 10 chiffres au Canada supportent uniquement la voix via ACS. Le SMS n'est pas disponible. Vous devez utiliser un numéro sans-frais.

Q: Combien de temps avant que mon numéro soit utilisable?¶

R:

  • Acquisition: 5 min (statut Unverified)
  • Vérification: 1–15 jours ouvrables (statut Verified)
  • Total: 1–15 jours de délai avant le premier SMS

Q: Et si la vérification toll-free est rejetée?¶

R: Microsoft enverra une notification expliquant pourquoi (ex. : information manquante, cas d'usage insuffisant). Corrigez la demande et resoumettez. Attendez-vous à +5–10 jours.

Q: Dois-je compléter l'EFVP (Loi 25) avant ou après la vérification toll-free?¶

R: La vérification toll-free peut commencer immédiatement. L'EFVP doit être complétée AVANT la mise en production. Vous pouvez les paralléliser pendant les semaines 2–3.

Q: Les employés ont-ils besoin d'un consentement écrit pour le SMS?¶

R: Pour les SMS d'urgence et de sécurité, la relation d'emploi suffit (exemption CASL). Cependant, le consentement documenté (via contrat, manuel) est recommandé pour des raisons d'audit et de conformité Loi 25.

Q: ACS gère-t-il automatiquement les STOP comme Twilio?¶

R: Non. ACS reçoit les messages STOP mais ne supprime pas automatiquement les destinataires. Vous devez implémenter un webhook (Event Grid) qui écoute les SMS entrants et met à jour votre table SmsOptOut.

Q: Quel est le coût exact?¶

R:

  • $2.00 CAD/mois par numéro (locationaires)
  • $0.0085 CAD par segment SMS (160 caractères, accents = 70)
  • Aucun frais pour les SMS entrants (STOP/ARRET)

Exemple: 1 000 SMS/mois + 1 numéro = $2.00 + ~$8.50 = ~$10.50 CAD/mois

Q: Puis-je utiliser un numéro toll-free pour la voix ET le SMS?¶

R: Oui. Un numéro sans-frais acquis pour le SMS supportera aussi la voix si vous le configurez (IVR, transferts, etc.). Les deux canaux sont autorisés.

Support et dépannage¶

Erreurs courantes lors de la soumission du formulaire¶

Erreur Cause probable Solution
"Country must be Canada" Adresse invalide ou non-canadienne Utilisez une adresse physique complète au Canada
"Use case description too short" Moins de 50 caractères Détaillez votre cas (ex. : "Emergency safety notifications to 300+ employees")
"No valid contact person" Courriel ou téléphone invalide Utilisez le courriel professionnel et le numéro complet
"Submission failed" Timeout ou erreur réseau Attendre 5 min et réessayer; vérifier la connexion

Signification du statut du numéro¶

Statut Signification Actions
Unverified 🔴 Nouvellement acquis; en attente de vérification Soumettre le formulaire toll-free
Verification Pending ⏳ Formulaire soumis; Microsoft examine Attendre (1–15 jours ouvrables)
Verified 🟢 Approuvé; prêt pour les SMS Configurer la connexion et tester
Verification Failed 🔴 Rejeté; répondre aux commentaires Lire l'email; corriger et resoumettele formulaire
Restricted 🟡 Restrictions temporaires appliquées Contacter support Azure pour détails

Prochaines étapes¶

Une fois votre numéro vérifié (Verified 🟢) :

  1. Stockez la chaîne de connexion dans Key Vault
  2. Implémentez le webhook Event Grid pour opt-out
  3. Déployez les tables SmsAuditLog et SmsOptOut dans Azure Storage
  4. Testez l'envoi et la réception avec un employé pilote
  5. Activez la fonction SMS en production
  6. Notifiez les employés de la nouvelle capacité SMS

Pour l'implémentation technique, consultez Guide d'intégration API SMS.
