Configuration des permissions SharePoint — Octroi Sites.Selected¶

Vue d'ensemble¶

Ce projet utilise Microsoft Graph API avec la permission d'application Sites.Selected — une portée à moindre privilège qui n'accorde l'accès qu'aux sites SharePoint explicitement autorisés. Contrairement à Sites.ReadWrite.All, elle ne donne pas à l'application un accès général à tous les sites du tenant.

Cependant, Sites.Selected requiert une configuration en deux étapes :

  1. Accorder la permission API Sites.Selected à l'inscription d'application dans Entra ID.
  2. Créer une permission au niveau du site via Graph API qui accorde à l'application un accès read ou write au site SharePoint spécifique.

Si l'étape 2 est manquante, les appels Graph API retournent 403 Access Denied même si l'application possède la permission Sites.Selected dans Entra ID.

Prérequis¶

  • Rôle d'Administrateur global ou d'Administrateur SharePoint pour le tenant Entra ID
  • L'identifiant d'application (client ID) et l'Object ID de l'inscription d'application ou de l'identité managée
  • L'identifiant du site SharePoint (format : {hostname},{site-collection-id},{web-id})
  • Microsoft Graph Explorer ou Azure CLI az rest

Étape 1 : Accorder la permission d'application Sites.Selected¶

Dans le portail Azure :

  1. Naviguez vers Entra ID → Inscriptions d'applications → sélectionnez votre application
  2. Allez à Permissions API → Ajouter une permission
  3. Sélectionnez Microsoft Graph → Permissions d'application
  4. Recherchez Sites.Selected et cochez-la
  5. Cliquez sur Ajouter des permissions
  6. Cliquez sur Accorder le consentement administrateur (requiert un rôle administrateur)

Pour une identité managée (assignée par le système) :

# Obtenir l'Object ID du principal de service de l'identité managée
az ad sp show --id <client-id-identite-managee> --query id -o tsv

# Accorder Sites.Selected via PowerShell (requiert le module Microsoft.Graph PowerShell)
Connect-MgGraph -Scopes "AppRoleAssignment.ReadWrite.All"

$graphAppId = "00000003-0000-0000-c000-000000000000"  # Microsoft Graph
$graphSp = Get-MgServicePrincipal -Filter "appId eq '$graphAppId'"

$sitesSelectedRole = $graphSp.AppRoles | Where-Object { $_.Value -eq "Sites.Selected" }

New-MgServicePrincipalAppRoleAssignment `
    -ServicePrincipalId <object-id-sp-identite-managee> `
    -PrincipalId <object-id-sp-identite-managee> `
    -ResourceId $graphSp.Id `
    -AppRoleId $sitesSelectedRole.Id

Étape 2 : Créer la permission au niveau du site (L'ÉTAPE CRITIQUE)¶

C'est l'étape la plus souvent oubliée. Même avec Sites.Selected accordée dans Entra ID, l'application n'a aucun accès aux sites tant que vous ne l'autorisez pas explicitement pour chaque site.

Avec Graph Explorer ou az rest¶

POST https://graph.microsoft.com/v1.0/sites/{siteId}/permissions

{
  "roles": ["write"],
  "grantedToIdentities": [
    {
      "application": {
        "id": "<application-client-id>",
        "displayName": "<nom-affichage-application>"
      }
    }
  ]
}

Avec Azure CLI :

az rest --method POST \
  --url "https://graph.microsoft.com/v1.0/sites/{siteId}/permissions" \
  --headers "Content-Type=application/json" \
  --body '{
    "roles": ["write"],
    "grantedToIdentities": [{
      "application": {
        "id": "<application-client-id>",
        "displayName": "EquipeLaurence Function App"
      }
    }]
  }'

Trouver l'identifiant du site¶

L'identifiant du site a le format {hostname},{site-collection-id},{web-id}. Pour le trouver :

# Par URL du site
az rest --method GET \
  --url "https://graph.microsoft.com/v1.0/sites/{hostname}:/sites/{chemin-site}"

# Exemple :
az rest --method GET \
  --url "https://graph.microsoft.com/v1.0/sites/contoso.sharepoint.com:/sites/HRDocuments"

Le champ id de la réponse est l'identifiant complet du site à utiliser dans la configuration (SharePoint:SiteId).

Étape 3 : Vérifier la permission¶

Listez les permissions existantes sur le site pour confirmer votre octroi :

az rest --method GET \
  --url "https://graph.microsoft.com/v1.0/sites/{siteId}/permissions"

Vous devriez voir une entrée avec l'identifiant client de votre application et le rôle write.

Utilisation de la validation intégrée¶

Le SharePointClient inclut une méthode ValidateAccessAsync() qui tente de lire la racine du lecteur. Si l'appel échoue avec un 403, une exception SharePointAccessDeniedException est levée avec des directives de remédiation exploitables. Cela peut être appelé :

  • Au démarrage de l'application pour un diagnostic rapide (fail-fast)
  • Depuis un point de terminaison HTTP de vérification de santé ou de diagnostic
  • Manuellement via le HTTP trigger de l'Azure Function

Dépannage¶

Symptôme Cause probable Correctif
403 avec le code accessDenied Étape 2 non complétée — aucune permission au niveau du site Créer la permission de site via POST /sites/{siteId}/permissions
403 avec le code invalidAuthenticationToken Sites.Selected non accordée ou consentement administrateur manquant Compléter l'étape 1 et cliquer sur « Accorder le consentement administrateur »
401 Unauthorized Échec d'acquisition du jeton — identité managée non configurée Vérifier que le Function App a l'identité managée assignée par le système activée
403 après déploiement dans un nouvel environnement La permission de site est par site, pas par environnement Répéter l'étape 2 pour l'identifiant du site du nouvel environnement
InvalidOperationException : « Graph API did not return an upload session » DriveId incorrect ou le lecteur n'existe pas Vérifier SharePoint:DriveId dans App Configuration

Référence de configuration¶

Paramètre Source Exemple
SharePoint:SiteId App Configuration contoso.sharepoint.com,abc123,def456
SharePoint:DriveId App Configuration b!xxxxx
SharePoint:RootFolder App Configuration /FSources/Nethris

Liste de vérification par environnement¶

Pour chaque environnement (dev, test, prod) :

  • L'inscription d'application / l'identité managée possède la permission Sites.Selected avec le consentement administrateur
  • La permission au niveau du site a été créée via POST /sites/{siteId}/permissions avec le rôle write
  • SharePoint:SiteId et SharePoint:DriveId sont configurés dans App Configuration
  • ValidateAccessAsync() retourne avec succès (aucune SharePointAccessDeniedException)
