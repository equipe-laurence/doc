Guide d'intégration API SMS¶

Ce guide documente l'API SMS actuelle basée sur Twilio avec authentification Entra ID (Azure AD).

Portée¶

  • Envoi d'un lot SMS d'urgence aux destinataires éligibles d'un ou plusieurs bureaux (formulaire HTML + send-by-bureau, ou API JSON sms/send)
  • Consultation de l'historique de diffusion (sms/broadcasts)
  • Réception des SMS entrants Twilio (webhook sms/inbound/twilio, mots-clés STOP/START)
  • Réception des rapports de livraison ACS via Event Grid (sms/delivery-status) — aucun callback de statut Twilio n'est implémenté à ce jour

Le fournisseur d'envoi est sélectionné par Sms:Provider (Twilio | Acs | Disabled, voir Guide de configuration du fournisseur SMS). Seul Twilio envoie réellement des SMS : avec Acs ou Disabled, l'envoi est refusé par le DisabledSmsClient (erreur SmsDisabled par destinataire).

Authentification Entra ID¶

Tous les endpoints SMS (sauf le webhook Twilio sms/inbound/twilio et l'endpoint Event Grid sms/delivery-status, qui sont exclus de l'Easy Auth) nécessitent une authentification par jeton Bearer JWT émis par votre locataire Entra ID.

Flux d'authentification¶

  1. Inscrire l'application dans Entra ID (Tenant ID, Client ID, secret)
  2. Obtenir un token via MSAL, Azure CLI, ou flow client credentials (audience api://<client-id> par défaut)
  3. Ajouter le header Bearer à chaque requête (derrière Easy Auth, le jeton peut aussi arriver via X-MS-TOKEN-AAD-ACCESS-TOKEN)
  4. Le système valide le token (émetteur, audience) : tout utilisateur authentifié est autorisé — aucune appartenance à un groupe n'est vérifiée par le code

Obtenir un token Entra ID¶

Via Azure CLI (développement local) :

az account get-access-token --resource api://votre-client-id --query accessToken -o tsv

Via MSAL (client credentials, pour service-to-service) :

curl -X POST "https://login.microsoftonline.com/<tenant-id>/oauth2/v2.0/token" \
  -d "client_id=<client-id>" \
  -d "client_secret=<client-secret>" \
  -d "scope=api://votre-client-id/.default" \
  -d "grant_type=client_credentials"

Via MSAL (desktop app, pour utilisateurs interactifs) :

Utilisez la librairie MSAL.NET ou MSAL.js pour obtenir un token interactif.

Matrice des endpoints¶

Méthode Route Authentification Description
GET /api/notifications/sms/form Bearer Entra ID (redirection de connexion si Easy Auth + navigateur) Retourne le formulaire HTML de sélection
POST /api/notifications/sms/send-by-bureau Bearer Entra ID Envoie un SMS d'urgence aux destinataires éligibles d'un ou plusieurs bureaux (form-encoded)
POST /api/sms/send Bearer Entra ID Envoie un SMS d'urgence à un bureau (JSON, Idempotency-Key obligatoire)
GET /api/sms/broadcasts Bearer Entra ID Liste les diffusions récentes (30 jours, 100 max)
GET /api/sms/broadcasts/{idempotencyKey} Bearer Entra ID Détail d'une diffusion et statut de livraison par message
POST /api/sms/inbound/twilio Signature X-Twilio-Signature (HMAC-SHA1) Reçoit les SMS entrants Twilio (STOP/START)
POST /api/sms/delivery-status Aucune (Event Grid, exclu de l'Easy Auth) Reçoit les rapports de livraison ACS

1) GET /api/notifications/sms/form¶

Retourne un formulaire HTML (en français) listant les bureaux distincts de la table BaseTi avec le nombre de destinataires éligibles (cases locationCode, sélection multiple), un choix de niveau d'urgence (urgencyLevel) et le message (messageBody). Le formulaire soumet en fetch vers POST /api/notifications/sms/send-by-bureau (credentials: include).

Headers requis¶

Authorization: Bearer <token-entra-id>

Réponse 200¶

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<!DOCTYPE html>
<html lang="fr">
  <head>
    <title>Envoi SMS — Équipe Laurence</title>
  </head>
  <body>
    <form id="smsForm" method="POST" action="/api/notifications/sms/send-by-bureau">
      <input type="checkbox" name="locationCode" value="MTL" data-count="12" />
      <input type="checkbox" name="locationCode" value="TOR" data-count="5" />
      <input type="radio" name="urgencyLevel" value="info" checked />
      <input type="radio" name="urgencyLevel" value="important" />
      <input type="radio" name="urgencyLevel" value="urgent" />
      <textarea name="messageBody" id="messageBody" required></textarea>
      <button type="submit">Envoyer</button>
    </form>
  </body>
</html>

(Extrait simplifié ; les codes de bureau et les compteurs proviennent de BaseTi.)

Erreurs possibles¶

  • 401 Unauthorized — Token manquant ou invalide (avec Easy Auth actif et un navigateur Accept: text/html, redirection vers /.auth/login/aad à la place)
  • 500 Internal Server Error — Erreur lors de la lecture de BaseTi

2) POST /api/notifications/sms/send-by-bureau¶

Envoie un SMS à tous les destinataires éligibles d'un ou plusieurs locationCode. Les destinataires sont résolus depuis BaseTi (table Azure Table Storage alimentée par la synchronisation Nethris), filtrés sur IsEligibleForSms puis sur le registre d'opt-out (SmsOptOut).

Headers requis¶

Authorization: Bearer <token-entra-id>
Content-Type: application/x-www-form-urlencoded
Idempotency-Key: <cle-unique-uuid> (recommandé; généré si absent)

Requête (form-encoded)¶

Champ Obligatoire Description
locationCode oui Code de bureau ; répétable pour plusieurs bureaux (valeurs vides ignorées, doublons retirés)
messageBody oui Corps du message
urgencyLevel non info (préfixe ℹ️), important (⚠️) ou urgent (🚨) ; toute autre valeur = aucun préfixe 
locationCode=MTL&locationCode=TOR&urgencyLevel=urgent&messageBody=Alerte+securite+evacuation

Réponse 200¶

auditId reprend la valeur de Idempotency-Key (générée si absente). totalEmployees = nombre de destinataires éligibles non désinscrits. Le numéro est masqué (**** + 4 derniers chiffres).

{
  "locationCodes": ["MTL", "TOR"],
  "urgencyLevel": "urgent",
  "totalEmployees": 5,
  "sent": 4,
  "failed": 1,
  "auditId": "3f1c9d1e-7a52-4c1e-9d2b-0a1b2c3d4e5f",
  "details": [
    {
      "employeeNumber": "000123",
      "name": "Jean Tremblay",
      "phone": "****7890",
      "status": "sent",
      "messageId": "SMxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
      "timestamp": "2026-05-22T18:32:15Z"
    },
    {
      "employeeNumber": "000124",
      "name": "Marie Côté",
      "phone": "****1234",
      "status": "failed",
      "error": "TwilioError:21211",
      "timestamp": "2026-05-22T18:32:15Z"
    }
  ]
}

Valeurs possibles de error par destinataire : TwilioError:<code Twilio>, UnexpectedError, SmsDisabled (fournisseur Acs/Disabled). La réponse reste 200 même si tous les envois échouent.

Erreurs possibles¶

  • 400 Bad Request — {"error":"MissingLocationCode"} ou {"error":"MissingMessageBody"}
  • 401 Unauthorized — Token manquant ou expiré
  • 404 Not Found — {"error":"NoRecipientsFound","locationCodes":[...]} (aucun enregistrement) ou {"error":"NoEligibleRecipientsFound","locationCodes":[...]} (tous inéligibles ou désinscrits)
  • 500 Internal Server Error — Exception non gérée (corps vide)

2b) POST /api/sms/send¶

Variante JSON pour un seul bureau, destinée aux clients API. Même résolution des destinataires et même filtrage opt-out que send-by-bureau.

Headers requis¶

Content-Type: application/json
Idempotency-Key: <cle-unique-uuid> (obligatoire)

(plus l'en-tête Authorization Bearer décrit ci-dessus)

Requête (JSON)¶

{ "locationCode": "MTL", "messageBody": "Bonjour {firstName}, alerte sécurité" }

Variables de gabarit remplacées par destinataire (insensibles à la casse) : {firstName}, {lastName}, {fullName}, {employeeNumber}, {locationCode}.

Réponse 200¶

{
  "locationCode": "MTL",
  "totalRecipients": 4,
  "sent": 3,
  "failed": 1,
  "results": [
    { "employeeNumber": "000123", "success": true, "messageId": "SMxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" },
    { "employeeNumber": "000124", "success": false, "error": "TwilioError:21211" }
  ]
}

Erreurs possibles¶

  • 400 Bad Request — {"error":"MissingIdempotencyKey"}, {"error":"InvalidJsonBody"}, {"error":"MissingLocationCode"} ou {"error":"MissingMessageBody"}
  • 401 Unauthorized — Token manquant ou expiré
  • 404 Not Found — {"error":"NoRecipientsFound","locationCode":"MTL"}

Déploiement : infra/modules/functionApp.bicep positionne AzureWebJobs.SendEmergencySms.Disabled=true tant que le paramètre Bicep smsEnabled est false (valeur par défaut dans tous les environnements) ; cet endpoint est alors désactivé.

2c) GET /api/sms/broadcasts et GET /api/sms/broadcasts/{idempotencyKey}¶

Historique des diffusions, lu dans la table d'audit SmsAuditLog. Authentification Bearer Entra ID (401 sinon). Aucun paramètre de requête : la liste couvre les 30 derniers jours, 100 diffusions maximum, de la plus récente à la plus ancienne.

Réponse 200 — liste¶

[
  {
    "timestampUtc": "2026-05-22T18:32:15Z",
    "requesterPrincipal": "jean.tremblay@exemple.com",
    "locationCode": "MTL",
    "recipientCount": 4,
    "filteredOptOutCount": 1,
    "idempotencyKey": "3f1c9d1e-7a52-4c1e-9d2b-0a1b2c3d4e5f"
  }
]

Réponse 200 — détail¶

Le détail joint, pour chaque messageId de la diffusion, le statut stocké dans SmsDeliveryStatus ; sans rapport de livraison reçu, le statut est pending. deliveredCount regroupe delivered/read, failedCount regroupe failed/undelivered, le reste est pendingCount.

{
  "broadcast": { "timestampUtc": "2026-05-22T18:32:15Z", "requesterPrincipal": "jean.tremblay@exemple.com", "locationCode": "MTL", "recipientCount": 4, "filteredOptOutCount": 1, "idempotencyKey": "3f1c9d1e-7a52-4c1e-9d2b-0a1b2c3d4e5f" },
  "deliveredCount": 3,
  "failedCount": 0,
  "pendingCount": 1,
  "recipients": [
    { "messageId": "SMxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx", "status": "delivered", "toE164": "+1******7890", "updatedAtUtc": "2026-05-22T18:32:20Z" },
    { "messageId": "SMyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy", "status": "pending" }
  ]
}

Erreurs possibles¶

  • 401 Unauthorized — Token manquant ou expiré
  • 404 Not Found — Clé d'idempotence inconnue (détail uniquement, corps vide)

3) POST /api/sms/inbound/twilio¶

Webhook Twilio « A message comes in » (route : sms/inbound/twilio, fonction TwilioInboundSms). Exclu de l'Easy Auth ; l'authentification repose sur la signature Twilio.

Headers¶

  • Content-Type: application/x-www-form-urlencoded (sinon 400 Bad Request)
  • X-Twilio-Signature : HMAC-SHA1 (base64) de l'URL complète + paramètres triés, calculé avec Twilio:AuthToken (l'URL est reconstruite avec X-Forwarded-Proto/X-Forwarded-Host si présents). Signature absente ou invalide → 403 Forbidden.

Payload attendu (form-encoded)¶

From=%2B15145557890&Body=STOP

Seuls From et le premier mot de Body (insensible à la casse) sont utilisés. Sans From, la requête est ignorée.

Mots-clés traités¶

  • STOP, STOPALL, UNSUBSCRIBE, CANCEL, END, QUIT, ARRET → Ajout au registre opt-out (SmsOptOut)
  • START, UNSTOP, YES → Retrait du registre opt-out
  • Tout autre mot est ignoré (journalisé uniquement)

Réponse¶

Toujours 200 OK, Content-Type: text/xml, avec un TwiML vide : <?xml version="1.0" encoding="UTF-8"?><Response></Response> (aucune réponse SMS automatique).

Il n'existe aucune fonction pour les SMS entrants ACS : le helper AcsIncomingSmsData n'est utilisé par aucune fonction.

4) POST /api/sms/delivery-status¶

Endpoint Event Grid (fonction AcsDeliveryStatus) pour recevoir les rapports de livraison SMS ACS. Il n'existe pas de callback équivalent pour Twilio : avec le fournisseur Twilio, les messages restent pending dans l'historique de diffusion.

L'endpoint est exclu de l'Easy Auth et ne valide aucune signature. Il répond aux événements Microsoft.EventGrid.SubscriptionValidationEvent (handshake) par 200 {"validationResponse":"<code>"}. Les événements Microsoft.Communication.SMSDeliveryReportReceived sont enregistrés puis la réponse est 204 No Content ; un corps JSON illisible ou vide donne 400 (InvalidEventGridPayload).

Payload attendu¶

[
  {
    "eventType": "Microsoft.Communication.SMSDeliveryReportReceived",
    "data": {
      "to": "+15145557890",
      "messageId": "acs-msg-123",
      "deliveryStatus": "Delivered",
      "deliveryStatusDetails": "",
      "tag": "broadcast-idempotency-key"
    }
  }
]

Stockage¶

  • Table : SmsDeliveryStatus
  • Clé : PartitionKey = 8 premiers caractères du MessageId, RowKey = MessageId
  • Colonnes : Status (normalisé en minuscules), ToE164 (numéro masqué avant persistance, ex. +1******7890), ErrorCode/ErrorMessage (copie de deliveryStatusDetails, uniquement pour failed/undelivered), UpdatedAt, BroadcastIdempotencyKey
  • tag est utilisé comme corrélation avec la diffusion (clé d'idempotence)
  • Un statut de rang inférieur à celui déjà stocké (ex. sent après delivered) est ignoré

Idempotence¶

  • Le header Idempotency-Key est obligatoire pour POST /api/sms/send (400 MissingIdempotencyKey sinon) et recommandé pour POST /api/notifications/sms/send-by-bureau (un UUID est généré si absent, ce qui désactive de fait la protection contre les retries)
  • La réponse 200 est mise en cache dans la table SmsIdempotency (PartitionKey = idempotency, RowKey = clé) pendant 24 h
  • En cas de retry avec la même clé, la réponse mise en cache est rejouée sans renvoyer le lot
  • La clé est aussi transmise à l'enregistrement d'audit (SmsAuditLog) et sert de clé de lecture pour GET /api/sms/broadcasts/{idempotencyKey}

Codes d'erreur HTTP¶

Code Description
200 Succès — le lot a été traité (des envois individuels peuvent avoir échoué : voir failed / details)
204 Événements Event Grid enregistrés (delivery-status)
400 Requête malformée (champ obligatoire manquant, Idempotency-Key manquant sur sms/send, JSON invalide, payload Event Grid invalide, content type non form pour le webhook Twilio)
401 Token Entra ID manquant, expiré ou invalide
403 Signature X-Twilio-Signature invalide ou absente (webhook Twilio uniquement ; l'application ne vérifie pas d'appartenance à un groupe)
404 Aucun destinataire trouvé/éligible, ou diffusion inconnue (sms/broadcasts/{key})
500 Erreur serveur (exception non gérée dans send-by-bureau ou le formulaire)

Limites connues¶

  • GET /api/sms/broadcasts ne supporte pas de pagination ni de filtrage via query params (fenêtre fixe de 30 jours, 100 résultats max)
  • Les statuts de livraison ne sont alimentés que par la souscription Event Grid ACS (delivery-status) ; aucun callback de statut Twilio n'est implémenté, donc les diffusions Twilio apparaissent pending dans le détail
  • Aucune vérification d'appartenance à un groupe Entra ID n'est faite par le code : tout utilisateur authentifié peut envoyer (le paramètre AzureAd:AuthorizedGroupId provisionné par Bicep n'est lu par aucun code)
  • Le webhook sms/inbound/twilio n'est validé que par la signature Twilio : Twilio:AuthToken doit correspondre au compte qui appelle le webhook
