Guide de synchronisation Nethris → SharePoint¶

1. Vue d'ensemble¶

L'intégration Nethris → SharePoint transfère automatiquement les rapports RH générés par Nethris vers une bibliothèque de documents SharePoint. Le processus est entièrement automatisé et s'exécute chaque nuit. Il peut également être déclenché manuellement à la demande.

Ce que le système fait :

  • Se connecte à l'API Nethris et récupère la liste des rapports disponibles.
  • Vérifie dans un registre de synchronisation si chaque rapport a déjà été traité afin d'éviter les doublons.
  • Télécharge les nouveaux rapports depuis Nethris.
  • Dépose chaque rapport dans le bon dossier de la bibliothèque de documents SharePoint.
  • Consigne le résultat dans le registre de synchronisation.
  • Retourne un résumé indiquant combien de rapports ont été envoyés, ignorés ou ont échoué.

2. Flux de synchronisation de bout en bout¶

Déclencheur (timer automatique toutes les minutes  OU  appel HTTP manuel)
  │
  ▼
Connexion à Nethris
  → Obtention d'un identifiant de session (sessionId)
  │
  ▼
Récupération de la liste des rapports disponibles
  │
  ▼
Pour chaque rapport (du plus ancien au plus récent) :
  ├── Vérification dans le registre de synchronisation
  │     • Rapport déjà synchronisé → ignoré (statut : AlreadySynced)
  │     • Rapport nouveau → traitement continue
  │
  ├── Téléchargement du rapport depuis Nethris
  │
  ├── Dépôt du rapport dans SharePoint
  │     (dossier : FSources/Nethris/ — directement à la racine)
  │
  └── Enregistrement dans le registre de synchronisation
        • Succès → statut : Uploaded
        • Échec   → statut : Failed (les autres rapports continuent)
  │
  ▼
Déconnexion de Nethris (toujours exécutée, même en cas d'erreur)
  │
  ▼
Retour du résumé :
  nombre de rapports envoyés / ignorés / échoués

Note : Un échec sur un rapport individuel n'interrompt pas le traitement des autres rapports. Chaque rapport est traité de façon indépendante.

3. Structure des dossiers SharePoint¶

Les rapports sont déposés dans la bibliothèque de documents SharePoint selon la hiérarchie suivante :

Bibliothèque de documents SharePoint
└── FSources/
    └── Nethris/
        └── {NomRapport}_{aaaammjj_HHmmss}.{ext}

Exemple :

FSources/
└── Nethris/
    ├── Emp2_20260501_010140.xlsx
    └── Nom00_20260501_010140.xlsx

Format du nom de fichier :

Élément Description Exemple
{NomRapport} Nom du rapport (caractères spéciaux remplacés par _) BD_Emp2
{aaaammjj_HHmmss} Horodatage UTC de la génération du rapport 20260512_030012
{ext} Extension selon le format Nethris (pdf, csv, xlsx, xls) pdf

4. Déclenchement automatique (toutes les minutes)¶

La synchronisation est déclenchée automatiquement par un timer configurable qui s'exécute toutes les minutes. À chaque déclenchement, seuls les nouveaux rapports (non encore synchronisés) sont transférés vers SharePoint.

Configuration du déclencheur automatique (schedule timer)¶

Le déclencheur utilise une clé de configuration pour déterminer la fréquence d'exécution :

  • Expression du trigger dans le code : %Nethris:SyncSchedule%
  • En local (fichier local.settings.json -> Values) : clé Nethris__SyncSchedule
  • Sur Azure (Application Settings) : utiliser Nethris__SyncSchedule (portable Windows/Linux)

Exemple de configuration locale (local.settings.json) :

{
  "IsEncrypted": false,
  "Values": {
    // ...autres clés...
    "Nethris__SyncSchedule": "0 * * * * *" // toutes les minutes (pour tests locaux)
  }
}

Exemple de configuration Azure (Application Settings) :

Name Value
Nethris__SyncSchedule 0 * * * * *

Syntaxe CRON attendue : second minute hour day month day-of-week

  • 0 * * * * * : toutes les minutes

⚠️ Important : Ne modifiez jamais la valeur du schedule directement dans le code. Utilisez toujours la clé de configuration pour éviter tout incident de fréquence en production. ⚠️ Important : la variable d'environnement utilise __, tandis que l'expression de binding dans le code utilise :.

Pour surveiller les résultats, consultez Application Insights dans le portail Azure.

5. Déclenchement manuel via HTTP¶

Vous pouvez déclencher la synchronisation à tout moment via un appel HTTP. Cela est utile lorsque vous avez besoin de récupérer des rapports en dehors du cycle automatique.

5.0 Obtenir l'URL et la clé de fonction depuis le portail Azure¶

Avant d'appeler l'endpoint, vous devez récupérer deux valeurs dans le portail Azure.

Étape 1 — Trouver le nom de la Function App¶

  1. Connectez-vous au portail Azure.
  2. Dans la barre de recherche en haut, tapez EquipeLaurence et sélectionnez la ressource de type Function App dans les résultats.
  3. Le nom affiché dans le titre de la ressource (ex. : eql3-prod-func-xxxxx) est votre <function-app>.

💡 Vous pouvez aussi naviguer via Groupes de ressources → groupe eql3-prod-rg → repérez la ressource de type App Service avec l'icône éclair (⚡).

Étape 2 — Récupérer la clé de fonction¶

  1. Dans la page de la Function App, cliquez sur Fonctions dans le menu de gauche.
  2. Sélectionnez NethrisReportSyncFunction dans la liste.
  3. Cliquez sur Clés de fonction dans le menu de gauche de la fonction.
  4. Sous Clés de fonction, repérez la clé nommée default.
  5. Cliquez sur l'icône 👁 Afficher la valeur pour révéler la clé, puis copiez-la.

⚠️ Sécurité : Ne partagez jamais cette clé par courriel ou dans un document non sécurisé. Utilisez un gestionnaire de mots de passe ou le coffre de clés Azure pour la stocker.

Récapitulatif¶

Valeur à remplacer Où la trouver dans le portail Azure
<function-app> Nom de la ressource Function App (ex. : eql3-prod-func-xxxxx)
<function-key> Function App → Fonctions → NethrisReportSyncFunction → Clés de fonction → default

5.1 Informations de l'endpoint¶

Champ Valeur
Méthode GET
Route api/sync/nethris-reports
Auth Clé de fonction (header x-functions-key ou paramètre code)
URL complète https://<function-app>.azurewebsites.net/api/sync/nethris-reports?code=<function-key>

Remplacez <function-app> par le nom de votre Function App Azure et <function-key> par la clé de fonction fournie par votre équipe TI.

5.2 Guide pas à pas — Navigateur web¶

  1. Ouvrez un navigateur web.
  2. Collez l'URL complète dans la barre d'adresse en remplaçant les valeurs appropriées : 
    https://<function-app>.azurewebsites.net/api/sync/nethris-reports?code=<function-key>
  3. Appuyez sur Entrée.
  4. La page affichera un résultat JSON — reportez-vous à la section 6. Interpréter la réponse.

5.3 Guide pas à pas — PowerShell¶

$url = "https://<function-app>.azurewebsites.net/api/sync/nethris-reports?code=<function-key>"
$response = Invoke-RestMethod -Method Get -Uri $url
$response | ConvertTo-Json -Depth 5

5.4 Guide pas à pas — cURL (ligne de commande)¶

curl -s "https://<function-app>.azurewebsites.net/api/sync/nethris-reports?code=<function-key>"

5.5 Utilisation du header x-functions-key (alternative)¶

Si vous préférez ne pas exposer la clé dans l'URL :

curl -s \
  -H "x-functions-key: <function-key>" \
  "https://<function-app>.azurewebsites.net/api/sync/nethris-reports"

6. Interpréter la réponse¶

Une synchronisation réussie retourne un code HTTP 200 et un corps JSON structuré comme suit :

6.1 Exemple de réponse¶

{
  "startedAtUtc": "2026-05-12T03:00:01Z",
  "completedAtUtc": "2026-05-12T03:00:45Z",
  "totalReports": 3,
  "uploaded": 2,
  "skipped": 1,
  "failed": 0,
  "hasFailures": false,
  "outcomes": [
    {
      "reportProdId": "45875",
      "reportName": "BD_Emp2",
      "status": "Uploaded",
      "sharePointPath": "BD_Emp2_45875_20260510_010140.xlsx"
    },
    {
      "reportProdId": "45876",
      "reportName": "Nom00",
      "status": "AlreadySynced",
      "sharePointPath": null
    }
  ]
}

6.2 Description des champs du résumé¶

Champ Type Description
startedAtUtc Horodatage Date et heure de début de la synchronisation (UTC)
completedAtUtc Horodatage Date et heure de fin de la synchronisation (UTC)
totalReports Nombre Nombre total de rapports traités (envoyés + ignorés + échoués)
uploaded Nombre Nombre de rapports déposés avec succès dans SharePoint
skipped Nombre Nombre de rapports ignorés car déjà synchronisés
failed Nombre Nombre de rapports ayant échoué
hasFailures Booléen true si au moins un rapport a échoué, false sinon
outcomes Tableau Détail du résultat pour chaque rapport (voir section suivante)

6.3 Description des champs par rapport (outcomes)¶

Champ Type Description
reportProdId Texte Identifiant unique du rapport dans Nethris
reportName Texte Nom lisible du rapport
status Texte Résultat du traitement — voir tableau des statuts ci-dessous
sharePointPath Texte Chemin du fichier dans SharePoint (null si non déposé)

6.4 Valeurs du champ status¶

Valeur Signification
Uploaded Rapport téléchargé depuis Nethris et déposé dans SharePoint avec succès
AlreadySynced Rapport déjà présent dans le registre de synchronisation — ignoré pour éviter les doublons
Failed Échec du traitement de ce rapport (les autres rapports ont continué à être traités)

6.5 Codes de retour HTTP¶

Code HTTP Signification
200 Synchronisation terminée (même si certains rapports ont échoué — vérifiez hasFailures)
500 Erreur inattendue au niveau de la fonction — la synchronisation n'a pas pu démarrer

7. Cas courants et actions à prendre¶

Cas 1 — Synchronisation réussie, tous les rapports envoyés¶

Indicateurs :

  • hasFailures: false
  • failed: 0
  • Chaque entrée dans outcomes a le statut Uploaded

Action : Aucune action requise. Les rapports sont disponibles dans SharePoint.

Cas 2 — Tous les rapports déjà synchronisés¶

Indicateurs :

  • uploaded: 0
  • skipped égal à totalReports
  • Tous les statuts sont AlreadySynced

Action : Aucune action requise. Les rapports avaient déjà été déposés lors d'un cycle précédent. Il n'y a pas de nouveaux rapports à traiter.

Cas 3 — Échec partiel (certains rapports ont échoué)¶

Indicateurs :

  • hasFailures: true
  • failed supérieur à 0
  • Certaines entrées dans outcomes ont le statut Failed

Actions à prendre :

  1. Notez les reportProdId et reportName des rapports en échec.
  2. Vérifiez Application Insights pour consulter les messages d'erreur détaillés.
  3. Relancez manuellement la synchronisation après correction du problème (les rapports déjà envoyés seront ignorés automatiquement grâce au registre de déduplication).
  4. Si les échecs persistent, contactez l'équipe TI avec les reportProdId concernés et les messages d'erreur d'Application Insights.

Cas 4 — Erreur 500 (la synchronisation n'a pas démarré)¶

Indicateurs :

  • Code HTTP 500 retourné
  • Corps de la réponse : {"error": "An internal error occurred during sync."}

Actions à prendre :

  1. Consultez Application Insights pour identifier la cause de l'erreur.
  2. Vérifiez que les configurations Nethris et SharePoint sont accessibles (le coffre de clés Azure peut être temporairement indisponible).
  3. Relancez la synchronisation après quelques minutes.
  4. Si le problème persiste, contactez l'équipe TI.

Cas 5 — Aucune réponse ou délai d'attente dépassé¶

Indicateurs :

  • Le navigateur ou la commande ne répond pas dans un délai raisonnable (plus de 2 minutes).

Causes possibles :

  • L'application de fonction Azure est arrêtée ou en cours de démarrage à froid.
  • Problème réseau temporaire.

Actions à prendre :

  1. Patientez quelques minutes et réessayez.
  2. Vérifiez l'état de la Function App dans le portail Azure.
  3. Si le problème persiste, contactez l'équipe TI.
