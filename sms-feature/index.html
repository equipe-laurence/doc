SMS Feature — Azure Communication Services¶

Vue d'ensemble¶

Le module SMS Notifications envoie des SMS aux employés d'un bureau donné via Azure Communication Services (ACS). Les données d'employés proviennent d'un fichier Excel (BDNethris_BaseTI.xlsx). Les envois sont lancés par un formulaire HTML intégré; les confirmations de livraison sont enregistrées dans une piste d'audit.

Cas d'usage¶

  • Alertes d'urgence ou notifications critiques adressées aux équipes de bureaux spécifiques
  • Notification de fin de paie ou événements RH importants
  • Communication rapide sans dépendre du courrier électronique

Architecture¶

Flux d'envoi SMS¶

Demande utilisateur (formulaire HTML)
  ↓
GET /api/notifications/sms/form → formulaire HTML (liste des bureaux)
  ↓
Utilisateur sélectionne un bureau et compose le message
  ↓
POST /api/notifications/sms/send-by-bureau
  ↓
NethrisSmsService
  ├─ charge BDNethris_BaseTI.xlsx
  ├─ filtre les employés du bureau sélectionné
  ├─ pour chaque employé:
  │   ├─ formatte le numéro de téléphone
  │   ├─ appelle ACS pour envoyer le SMS
  │   └─ enregistre la confirmation de livraison
  └─ retourne le résumé (envoyés / échoués / totaux)
  ↓
Piste d'audit dans Azure Table Storage (table `SmsAudit`)

Prérequis d'authentification Entra ID¶

Les endpoints SMS de ce système sont protégés par Azure Entra ID (anciennement Azure AD). L'authentification par jeton Bearer JWT est requise pour tous les appels d'API.

1. Inscription de l'application dans Entra ID¶

Une application doit être inscrite dans votre locataire Azure Entra ID pour utiliser les endpoints SMS. Contactez votre administrateur Entra ID pour :

  1. Créer une nouvelle application enregistrée (ex: "EquipeLaurence SMS API")
  2. Définir un URI d'audience (ex: api://equipe-laurence-sms ou utiliser le Client ID par défaut)
  3. Configurer l'authentification : Web → URIs de redirection
  4. Générer un secret client (pour les appels de service à service)
  5. Obtenir les identifiants :
  6. Tenant ID (identifiant du répertoire)
  7. Client ID (identifiant de l'application)
  8. Client Secret (pour l'authentification de service)

2. Entra ID pour les SMS¶

L'accès aux endpoints SMS est contrôlé par l'authentification Entra ID. Tout utilisateur authentifié est autorisé — aucune appartenance à un groupe spécifique n'est requise.

3. Permissions Microsoft Graph¶

Le Function App utilise le permission Graph Sites.Selected pour écrire dans SharePoint. Cette permission est limités au site cible et ne peut être accordée via consentement OAuth standard — elle nécessite une configuration manuelle par l'administrateur après le déploiement.

API Endpoints (Implémentés)¶

1. GET /api/notifications/sms/form¶

Description: Retourne un formulaire HTML pour sélectionner un bureau et composer un message SMS.

Authentification: [Authorize] — Entra ID requis; tout utilisateur authentifié est autorisé.

Headers attendus:

Authorization: Bearer <token-entra-id>

Obtenir un token d'Entra ID (MSAL):

# Via Azure CLI (développement local)
az account get-access-token --resource api://votre-client-id --query accessToken -o tsv

# Ou via curl (client credentials flow, pour service-to-service)
curl -X POST "https://login.microsoftonline.com/<tenant-id>/oauth2/v2.0/token" \
  -d "client_id=<client-id>" \
  -d "client_secret=<client-secret>" \
  -d "scope=api://votre-client-id/.default" \
  -d "grant_type=client_credentials"

Réponse:

HTTP/1.1 200 OK Content-Type: text/html; charset=utf-8

<!DOCTYPE html>
<html>
  <head>
    <title>SMS Notification Form</title>
    <meta charset="UTF-8" />
  </head>
  <body>
    <h1>Envoyer un SMS aux employés</h1>

    <form method="POST" action="/api/notifications/sms/send-by-bureau">
      <label for="bureau">Bureau:</label>
      <select name="bureau" id="bureau" required>
        <option value="">-- Sélectionner un bureau --</option>
        <option value="MTL">Montréal</option>
        <option value="TOR">Toronto</option>
        <option value="QUE">Québec</option>
      </select>

      <label for="message">Message:</label>
      <textarea name="message" id="message" rows="4" required></textarea>

      <button type="submit">Envoyer</button>
    </form>
  </body>
</html>

Erreurs possibles:

  • 401 Unauthorized — Token manquant ou invalide
  • 403 Forbidden — Utilisateur authentifié mais pas membre du groupe SMS autorisé

2. POST /api/notifications/sms/send-by-bureau¶

Description: Envoie un SMS à tous les employés du bureau sélectionné.

Authentification: [Authorize] — Entra ID requis; tout utilisateur authentifié est autorisé.

Headers attendus:

Authorization: Bearer <token-entra-id>
Content-Type: application/x-www-form-urlencoded
Idempotency-Key: <uuid> (recommandé; généré automatiquement si absent)

Paramètres du corps (form-encoded):

locationCode=MTL&messageBody=Alerte%20de%20paie%20...

Réponse 200 OK:

Erreurs possibles:

  • 400 Bad Request — Paramètres manquants (bureau, message) ou invalides
  • 401 Unauthorized — Token manquant, expiré ou invalide
  • 403 Forbidden — Utilisateur authentifié mais pas membre du groupe SMS autorisé
  • 404 Not Found — Bureau inexistant ou aucun employé trouvé
  • 500 Internal Server Error — Erreur lors de l'accès à Twilio ou à la base de données

Configuration¶

1. Provisionner Azure Communication Services (Bicep)¶

ACS est automatiquement provisionné par le module infra/modules/acsService.bicep lors du déploiement.

Paramètres Bicep (infra/parameters/{env}.bicepparam):

param acsConnectionStringSecretName = 'acs-connection-string'
param acsPhoneNumberValue = ''  # Laisser vide initialement

Après le déploiement initial:

  1. Ouvrir Azure Portal → ACS → Phone Numbers
  2. Cliquer sur Acquire (ou Buy selon les régions)
  3. Sélectionner Canada et le type de numéro (SMS)
  4. Copier le numéro acquis (ex: +1-613-867-5309)
  5. Enregistrer ce numéro dans la variable GitHub d'environnement ACS_PHONE_NUMBER
  6. Relancer le déploiement pour que Bicep le stocke dans App Configuration sous Acs:PhoneNumber

2. Key Vault Secrets¶

Secret Name Description Stockage
acs-connection-string Chaîne de connexion primaire d'ACS Key Vault
acs-phone-number Numéro SMS sortant acquis Key Vault

3. App Configuration Keys¶

Clé Exemple Description
Acs:ConnectionString endpoint=https://... Référence secrète KV
Acs:PhoneNumber +1-613-867-5309 Numéro SMS sortant (stocké en clair en App Config)
Acs:Enabled true Active/désactive le module SMS

4. Code d'application (Program.cs)¶

// Lire les options ACS
builder.Services.Configure<AcsOptions>(config.GetSection(AcsOptions.SectionName));

// Enregistrer le client ACS
builder.Services
  .AddHttpClient<IAcsSmsClient, AcsSmsClient>()
  .AddTransientHttpErrorPolicy(p => p.WaitAndRetryAsync(
    retryCount: 3,
    sleepDurationProvider: retryAttempt => TimeSpan.FromMilliseconds(Math.Pow(2, retryAttempt) * 100),
    onRetry: (outcome, span, retryCount, context) =>
    {
      _logger.LogWarning($"SMS retry {retryCount} after {span.TotalMilliseconds}ms");
    }
  ));

// Enregistrer le service d'envoi SMS
builder.Services.AddScoped<INethrisSmsService, NethrisSmsService>();

5. Interface et Options (Core/Clients/)¶

public interface IAcsSmsClient
{
  /// <summary>
  /// Envoie un SMS à un destinataire.
  /// </summary>
  Task<SmsSendResult> SendSmsAsync(string toPhoneNumber, string messageBody, CancellationToken cancellationToken);
}

public class AcsOptions
{
  public const string SectionName = "Acs";

  public required string ConnectionString { get; init; }
  public required string PhoneNumber { get; init; }
  public bool Enabled { get; init; } = true;
}

public record SmsSendResult(
  string MessageId,
  bool Success,
  string? ErrorCode,
  string? ErrorMessage
);

6. Implémentation (Infrastructure/Clients/)¶

public class AcsSmsClient : IAcsSmsClient
{
  private readonly SmsClient _smsClient;
  private readonly ILogger<AcsSmsClient> _logger;

  public AcsSmsClient(IOptions<AcsOptions> options, ILogger<AcsSmsClient> logger)
  {
    _logger = logger;
    _smsClient = new SmsClient(new Uri(options.Value.ConnectionString));
  }

  public async Task<SmsSendResult> SendSmsAsync(string toPhoneNumber, string messageBody, CancellationToken cancellationToken)
  {
    try
    {
      var response = await _smsClient.SendAsync(
        from: _options.Value.PhoneNumber,
        to: toPhoneNumber,
        message: messageBody,
        options: new SendSmsOptions { EnableDeliveryReport = true },
        cancellationToken: cancellationToken
      );

      return new SmsSendResult(response.MessageId, true, null, null);
    }
    catch (Exception ex)
    {
      _logger.LogError(ex, "Failed to send SMS to {ToNumber}", toPhoneNumber);
      return new SmsSendResult(null, false, ex.GetType().Name, ex.Message);
    }
  }
}

Guide de déploiement¶

Environnement dev¶

# 1. Déployer l'infrastructure (crée ACS)
azd deploy --environment dev

# 2. Attendre ~5 min
# 3. Acquérir un numéro de téléphone dans Azure Portal (ACS → Phone Numbers)
# 4. Enregistrer le numéro dans la variable GitHub d'environnement ACS_PHONE_NUMBER
# 5. Re-déployer l'app pour le pousser dans App Configuration:
azd deploy --environment dev

Environnement prod¶

Même processus; adapter le nom du vault (ex: eql-prod-kv-xxxxx).

Guide de test local¶

Avec mocks¶

[Fact]
public async Task SendSmsAsync_WithValidPhoneNumber_ReturnsSuccess()
{
  // Arrange
  var mockLogger = new Mock<ILogger<AcsSmsClient>>();
  var options = Options.Create(new AcsOptions
  {
    ConnectionString = "endpoint=https://test.communication.azure.com/;accesskey=test",
    PhoneNumber = "+1-613-867-5309",
    Enabled = true
  });

  var mockAcsClient = new Mock<SmsClient>();
  mockAcsClient
    .Setup(x => x.SendAsync(It.IsAny<string>(), It.IsAny<string>(), It.IsAny<string>(), It.IsAny<SendSmsOptions>(), It.IsAny<CancellationToken>()))
    .ReturnsAsync(new SmsSendResult { MessageId = "msg-123", Status = "sent" });

  var sut = new AcsSmsClient(options, mockLogger.Object);

  // Act
  var result = await sut.SendSmsAsync("+1-514-555-7890", "Test SMS", CancellationToken.None);

  // Assert
  Assert.True(result.Success);
  Assert.Equal("msg-123", result.MessageId);
}

Conformité & Conformité¶

CASL (Loi canadienne anti-pourriel)¶

  • ✅ Consentement nécessaire avant d'envoyer des SMS (vérifier via formulaire)
  • ✅ Option de désabonnement (STOP / ARRET) disponible
  • ✅ Piste d'audit complète (table SmsAudit + métadonnées)

Voir docs/sms-compliance.md pour plus de détails.

Masquage des numéros¶

Tous les numéros téléphoniques affichés dans les réponses API sont masqués partiellement (ex: +1514***7890).

Dépannage¶

Problème Cause probable Solution
InvalidPhoneNumber Format de numéro incorrect Vérifier le format E.164 (+1514...)
AcsConnectionStringInvalid Secrets KV non chargés Vérifier app.settings / local.settings.json
NoEmployeesFound Bureau inexistant Vérifier la validité du code bureau dans Excel
SendSmsAsync timeout Réseau ou ACS indisponible Vérifier connectivité Azure + retry Polly
