SMS Feature — Twilio¶

Vue d'ensemble¶

Le module SMS Notifications envoie des SMS aux employés d'un ou plusieurs bureaux via Twilio (fournisseur actif ; Azure Communication Services est conservé en legacy mais n'est plus câblé à l'envoi — voir Guide de configuration du fournisseur SMS). Les destinataires proviennent de la table Azure Table Storage BaseTi, alimentée par la synchronisation Nethris (BDNethris_BaseTI.xlsx). Les envois sont lancés par un formulaire HTML intégré ou par l'API JSON; chaque diffusion est consignée dans une piste d'audit (SmsAuditLog) consultable via GET /api/sms/broadcasts.

Cas d'usage¶

  • Alertes d'urgence ou notifications critiques adressées aux équipes de bureaux spécifiques
  • Notification de fin de paie ou événements RH importants
  • Communication rapide sans dépendre du courrier électronique

Architecture¶

Flux d'envoi SMS¶

Demande utilisateur (formulaire HTML)
  ↓
GET /api/notifications/sms/form → formulaire HTML (bureaux issus de BaseTi + compteurs)
  ↓
Utilisateur sélectionne un ou plusieurs bureaux, un niveau d'urgence et compose le message
  ↓
POST /api/notifications/sms/send-by-bureau   (ou POST /api/sms/send en JSON)
  ↓
SendSmsByBureauFunction
  ├─ vérifie l'authentification Entra ID et l'Idempotency-Key (réponse rejouée depuis SmsIdempotency si connue)
  ├─ lit les destinataires de chaque bureau dans la table BaseTi (ISmsRecipientSource)
  ├─ exclut les inéligibles (IsEligibleForSms) et les numéros présents dans SmsOptOut
  ├─ pour chaque destinataire restant:
  │   └─ appelle ISmsClient (TwilioSmsClient, ou DisabledSmsClient si Sms:Provider ≠ Twilio)
  ├─ enregistre l'audit (SmsAuditLog) et met la réponse en cache (SmsIdempotency, 24 h)
  └─ retourne le résumé (envoyés / échoués / détails masqués)
  ↓
Piste d'audit dans Azure Table Storage (table `SmsAuditLog`)

Prérequis d'authentification Entra ID¶

Les endpoints SMS de ce système sont protégés par Azure Entra ID (anciennement Azure AD). L'authentification par jeton Bearer JWT est requise pour tous les appels d'API.

1. Inscription de l'application dans Entra ID¶

Une application doit être inscrite dans votre locataire Azure Entra ID pour utiliser les endpoints SMS. Contactez votre administrateur Entra ID pour :

  1. Créer une nouvelle application enregistrée (ex: "EquipeLaurence SMS API")
  2. Définir un URI d'audience (ex: api://equipe-laurence-sms ou utiliser le Client ID par défaut)
  3. Configurer l'authentification : Web → URIs de redirection
  4. Générer un secret client (pour les appels de service à service)
  5. Obtenir les identifiants :
  6. Tenant ID (identifiant du répertoire)
  7. Client ID (identifiant de l'application)
  8. Client Secret (pour l'authentification de service)

2. Entra ID pour les SMS¶

L'accès aux endpoints SMS est contrôlé par l'authentification Entra ID. Tout utilisateur authentifié est autorisé — aucune appartenance à un groupe spécifique n'est requise.

3. Permissions Microsoft Graph¶

Le Function App utilise le permission Graph Sites.Selected pour écrire dans SharePoint. Cette permission est limités au site cible et ne peut être accordée via consentement OAuth standard — elle nécessite une configuration manuelle par l'administrateur après le déploiement.

API Endpoints (Implémentés)¶

1. GET /api/notifications/sms/form¶

Description: Retourne un formulaire HTML (en français) pour sélectionner un ou plusieurs bureaux, un niveau d'urgence et composer un message SMS. Les bureaux et le nombre de destinataires éligibles proviennent de la table BaseTi.

Authentification: [Authorize] — Entra ID requis; tout utilisateur authentifié est autorisé.

Headers attendus:

Authorization: Bearer <token-entra-id>

Obtenir un token d'Entra ID (MSAL):

# Via Azure CLI (développement local)
az account get-access-token --resource api://votre-client-id --query accessToken -o tsv

# Ou via curl (client credentials flow, pour service-to-service)
curl -X POST "https://login.microsoftonline.com/<tenant-id>/oauth2/v2.0/token" \
  -d "client_id=<client-id>" \
  -d "client_secret=<client-secret>" \
  -d "scope=api://votre-client-id/.default" \
  -d "grant_type=client_credentials"

Réponse:

HTTP/1.1 200 OK Content-Type: text/html; charset=utf-8

<!DOCTYPE html>
<html lang="fr">
  <head>
    <title>Envoi SMS — Équipe Laurence</title>
    <meta charset="UTF-8" />
  </head>
  <body>
    <form id="smsForm" method="POST" action="/api/notifications/sms/send-by-bureau">
      <!-- une case par bureau issu de BaseTi (sélection multiple) -->
      <input type="checkbox" name="locationCode" value="MTL" data-count="12" />
      <input type="checkbox" name="locationCode" value="TOR" data-count="5" />

      <!-- niveau d'urgence : préfixe ℹ️ / ⚠️ / 🚨 ajouté au message -->
      <input type="radio" name="urgencyLevel" value="info" checked />
      <input type="radio" name="urgencyLevel" value="important" />
      <input type="radio" name="urgencyLevel" value="urgent" />

      <textarea name="messageBody" id="messageBody" required></textarea>
      <button type="submit">Envoyer</button>
    </form>
  </body>
</html>

Erreurs possibles:

  • 401 Unauthorized — Token manquant ou invalide (redirection vers /.auth/login/aad si Easy Auth est actif et que le client accepte text/html)
  • 500 Internal Server Error — Erreur lors de la lecture de BaseTi

2. POST /api/notifications/sms/send-by-bureau¶

Description: Envoie un SMS à tous les destinataires éligibles (non désinscrits) des bureaux sélectionnés.

Authentification: [Authorize] — Entra ID requis; tout utilisateur authentifié est autorisé.

Headers attendus:

Authorization: Bearer <token-entra-id>
Content-Type: application/x-www-form-urlencoded
Idempotency-Key: <uuid> (recommandé; généré automatiquement si absent)

Paramètres du corps (form-encoded): locationCode (répétable), messageBody, urgencyLevel (info | important | urgent, optionnel)

locationCode=MTL&locationCode=TOR&urgencyLevel=important&messageBody=Alerte%20de%20paie%20...

Réponse 200 OK:

{
  "locationCodes": ["MTL", "TOR"],
  "urgencyLevel": "important",
  "totalEmployees": 12,
  "sent": 10,
  "failed": 2,
  "auditId": "3f1c9d1e-7a52-4c1e-9d2b-0a1b2c3d4e5f",
  "details": [
    {
      "employeeNumber": "EMP001",
      "name": "John Doe",
      "phone": "****7890",
      "status": "sent",
      "messageId": "SMxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
      "timestamp": "2026-05-19T18:32:15Z"
    },
    {
      "employeeNumber": "EMP002",
      "name": "Jane Smith",
      "phone": "****7891",
      "status": "failed",
      "error": "TwilioError:21211",
      "timestamp": "2026-05-19T18:32:15Z"
    }
  ]
}

Erreurs possibles:

  • 400 Bad Request — MissingLocationCode ou MissingMessageBody
  • 401 Unauthorized — Token manquant, expiré ou invalide
  • 404 Not Found — NoRecipientsFound (aucun enregistrement pour les bureaux) ou NoEligibleRecipientsFound (tous inéligibles ou désinscrits)
  • 500 Internal Server Error — Exception non gérée

Voir Guide d'intégration API SMS pour POST /api/sms/send (JSON), GET /api/sms/broadcasts (historique) et le webhook entrant Twilio.

Configuration¶

1. Provisionner Twilio (Bicep)¶

Les secrets et clés Twilio sont provisionnés par le module infra/modules/twilioProvider.bicep lorsque smsProvider = 'Twilio' (valeur configurée dans infra/parameters/{env}.bicepparam). Le module ACS (acsService.bicep) n'est déployé que si smsProvider = 'Acs' (rollback).

Paramètres Bicep (infra/main.bicep):

param smsProvider = 'Twilio'          // 'Twilio' | 'Acs' | 'Disabled' (défaut : 'Disabled')
param twilioFromNumber = '+1...'      // numéro Twilio E.164 (App Configuration)
// twilioAccountSidValue / twilioAuthTokenValue : @secure, fournis par le pipeline (Key Vault)
param smsEnabled = false              // défaut : false dans tous les environnements

smsEnabled=false positionne Sms__Enabled=false et désactive la fonction SendEmergencySms (AzureWebJobs.SendEmergencySms.Disabled=true). Le code ne lit pas Sms__Enabled : seul Sms:Provider pilote le comportement d'envoi.

Voir Guide de configuration du fournisseur SMS et Guide d'acquisition d'un numéro Twilio.

2. Key Vault Secrets¶

Secret Name Description Stockage
twilio-account-sid Account SID Twilio Key Vault
twilio-auth-token Auth Token Twilio (sert aussi à valider X-Twilio-Signature) Key Vault

3. App Configuration Keys¶

Clé Exemple Description
Sms:Provider Twilio Twilio, Acs ou Disabled
Twilio:AccountSid Référence secrète KV Account SID
Twilio:AuthToken Référence secrète KV Auth Token
Twilio:FromNumber +15145550100 Numéro SMS sortant (stocké en clair en App Config)

4. Code d'application (FunctionAppStartup.cs)¶

Le fournisseur est sélectionné au démarrage par FunctionAppStartup.GetSmsProvider puis enregistré comme ISmsClient :

switch (smsProvider.ToLowerInvariant())
{
    case "twilio":
        services.AddSingleton<ISmsClient, TwilioSmsClient>();
        break;
    case "acs":
    default:
        services.AddSingleton<ISmsClient, DisabledSmsClient>();
        break;
}

Les options TwilioOptions (section Twilio, AccountSid/AuthToken/FromNumber obligatoires) sont validées au démarrage (ValidateOnStart) quel que soit le fournisseur. Le client ACS (Infrastructure.Acs) n'est pas référencé par le Function App.

5. Interface et résultat (Core/Clients/, Core/Models/)¶

public interface ISmsClient
{
  // Ne lève jamais d'exception : les erreurs sont retournées dans le résultat.
  Task<SmsSendResult> SendSmsAsync(
    string toE164, string body, string broadcastIdempotencyKey, CancellationToken cancellationToken = default);
}

public sealed record SmsSendResult
{
  public required bool Success { get; init; }
  public string? MessageId { get; init; }   // SID Twilio en cas de succès
  public string? Error { get; init; }       // "TwilioError:<code>", "UnexpectedError", "SmsDisabled"
}

6. Implémentation (Infrastructure.Twilio/Clients/)¶

TwilioSmsClient initialise TwilioClient avec Twilio:AccountSid/Twilio:AuthToken, envoie le message depuis Twilio:FromNumber via MessageResource.CreateAsync et retourne le SID comme MessageId. Les ApiException Twilio sont converties en TwilioError:<code>; toute autre exception en UnexpectedError. Les numéros sont masqués dans les journaux.

Guide de déploiement¶

Environnement dev¶

# 1. Déployer l'infrastructure (workflow GitHub Actions infra-deploy.yml, équivalent à:)
az deployment group create \
  --resource-group <rg> \
  --template-file infra/main.bicep \
  --parameters infra/parameters/dev.bicepparam

# 2. Créer/mettre à jour les secrets Key Vault `twilio-account-sid` et `twilio-auth-token`
#    (le workflow ne transmet pas twilioAccountSidValue / twilioAuthTokenValue)
# 3. Vérifier la clé App Configuration `Sms:Provider = Twilio` et `Twilio:FromNumber`
# 4. Déployer l'application (workflow function-deploy.yml)

Environnement prod¶

Même processus avec infra/parameters/prod.bicepparam; adapter le nom du vault (ex: eql-prod-kv-xxxxx).

Guide de test local¶

Avec mocks¶

Les tests unitaires du client Twilio se trouvent dans tests/EquipeLaurence.Infrastructure.Twilio.Tests/ (TwilioSmsClientTests), ceux des fonctions HTTP dans tests/EquipeLaurence.Functions.Tests/ (SendSmsByBureauFunctionTests, SendEmergencySmsFunctionTests, TwilioInboundSmsFunctionTests, BroadcastHistoryFunctionTests, etc.).

Tests d'intégration (avec Azurite local)¶

# 1. Démarrer Azurite (Azure Storage emulator)
azurite --silent --location ./AzuriteConfig

# 2. Exécuter les tests:
dotnet test tests/EquipeLaurence.Infrastructure.Tests --filter "FullyQualifiedName~TableStorage"

Tester manuellement via cURL¶

En développement local, Sms:BypassAuthInDevelopment=true (dans local.settings.json uniquement, avec l'environnement Development) permet d'appeler les endpoints SMS sans jeton.

# 1. Récupérer un token Azure AD:
TOKEN=$(az account get-access-token --resource api://<client-id> --query accessToken -o tsv)

# 2. Appeler le formulaire:
curl -X GET "http://localhost:7071/api/notifications/sms/form" -H "Authorization: Bearer $TOKEN"

# 3. Envoyer un SMS de test:
curl -X POST "http://localhost:7071/api/notifications/sms/send-by-bureau" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "locationCode=MTL&urgencyLevel=info&messageBody=Test%20SMS"

Conformité & Conformité¶

CASL (Loi canadienne anti-pourriel)¶

  • ✅ Consentement nécessaire avant d'envoyer des SMS (recueilli par les RH via Nethris; seuls les employés IsEligibleForSms sont ciblés)
  • ✅ Option de désabonnement (STOP / ARRET) disponible via le webhook Twilio POST /api/sms/inbound/twilio (table SmsOptOut)
  • ✅ Piste d'audit complète (table SmsAuditLog + hachage SHA-256 du message)

Voir docs/sms-compliance.md pour plus de détails.

Masquage des numéros¶

Les numéros affichés dans les réponses API de diffusion sont masqués (ex: ****7890); les rapports de livraison stockent un numéro masqué de la forme +1******7890.

Dépannage¶

Problème Cause probable Solution
SmsDisabled Sms:Provider absent, Disabled ou Acs Définir Sms:Provider = Twilio (App Configuration)
TwilioError:21211 Numéro invalide (format E.164 incorrect) Vérifier le numéro dans BaseTi (+1514...)
TwilioError:<code> Erreur API Twilio Consulter le code dans la documentation d'erreurs Twilio
NoRecipientsFound Aucun enregistrement BaseTi pour ce bureau Vérifier le code bureau et la dernière synchronisation Nethris
NoEligibleRecipientsFound Destinataires inéligibles ou désinscrits Vérifier IsEligibleForSms dans BaseTi et la table SmsOptOut
OptionsValidationException au démarrage Twilio:AccountSid/AuthToken/FromNumber manquants Vérifier App Configuration / Key Vault / local.settings.json
