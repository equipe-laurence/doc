2. Plan de tests manuels / Tests d'acceptation¶

2.1 Contexte et prérequis généraux¶

À propos du système¶

Le système Equipe Laurence est une application automatisée hébergée dans Microsoft Azure. Chaque nuit à 3 h (heure UTC), elle se connecte au système de paie Nethris, récupère tous les rapports automatisés disponibles, et les dépose dans une bibliothèque de documents SharePoint privée. Un registre interne empêche le dépôt en double d'un même rapport.

Le système peut également être déclenché manuellement via une URL sécurisée, ce qui permet de tester la synchronisation ou de récupérer des rapports en dehors du cycle automatique.

Prérequis pour l'exécution des tests d'acceptation¶

Avant de commencer les tests, s'assurer que les éléments suivants sont en place :

Prérequis Responsable Vérifié
L'application Azure Function est déployée (environnement de test ou production) Équipe technique ☐
Les identifiants Nethris (code utilisateur, mot de passe) sont configurés dans Azure Key Vault Équipe technique ☐
L'identité gérée de la Function App a les droits nécessaires sur SharePoint Équipe technique ☐
La bibliothèque de documents SharePoint cible existe et est accessible Client ☐
Le registre de synchronisation (Azure Table Storage) est opérationnel Équipe technique ☐
La personne effectuant les tests a accès aux journaux Azure (Application Insights) Client ou équipe ☐
La clé d'API de la fonction HTTP est disponible Équipe technique ☐

2.2 Scénarios d'acceptation¶

Scénario 1 — Synchronisation automatique réussie¶

Description : Vérifier que la synchronisation automatique s'exécute correctement toutes les minutes et dépose les rapports dans SharePoint.

Prérequis :

  • L'application est déployée et le déclencheur automatique est activé (toutes les minutes)
  • Des rapports sont disponibles dans Nethris
  • Aucun de ces rapports n'a été synchronisé précédemment

Étapes :

  1. Attendre le prochain déclenchement automatique (toutes les minutes)
  2. Après le déclenchement, ouvrir la bibliothèque de documents SharePoint cible
  3. Naviguer vers le dossier FSources/Nethris/{année}/{mois}/{jour}/ correspondant à la date d'exécution des rapports
  4. Vérifier que les fichiers sont présents

Résultat attendu :

  • Les rapports Nethris sont présents dans SharePoint sous le bon chemin de dossier
  • Chaque fichier porte un nom du format {NomRapport}_{IdentifiantRapport}_{dateHeure}.{extension}
  • Dans les journaux Azure, on lit : "Sync completed — X uploaded, 0 skipped, 0 failed"
Résultat observé Statut
☐ ✅ Réussi   ☐ ❌ Échec   ☐ ⚠️ Partiel

Scénario 2 — Synchronisation manuelle à la demande¶

Description : Vérifier que la synchronisation peut être déclenchée manuellement via l'URL sécurisée.

Prérequis :

  • La clé d'API (code=...) fournie par l'équipe technique est disponible
  • Des rapports nouveaux sont disponibles dans Nethris

Étapes :

  1. Dans un navigateur ou un outil de requêtes HTTP (ex. Bruno, Postman), exécuter une requête GET vers : https://{nom-de-la-function}.azurewebsites.net/api/sync/nethris-reports?code={clé-api}
  2. Attendre la réponse (peut prendre de quelques secondes à quelques minutes selon le nombre de rapports)
  3. Lire le corps de la réponse JSON
  4. Vérifier la présence des fichiers dans SharePoint

Résultat attendu :

  • La réponse HTTP est 200 OK
  • Le corps JSON contient un résumé du type : 
    { "uploaded": 3, "skipped": 0, "failed": 0, "outcomes": [...] }
  • Les fichiers sont visibles dans SharePoint dans les secondes qui suivent
Résultat observé Statut
☐ ✅ Réussi   ☐ ❌ Échec   ☐ ⚠️ Partiel

Scénario 3 — Prévention des doublons¶

Description : Vérifier que le système ne re-téléverse pas un rapport déjà synchronisé, même si la synchronisation est déclenchée plusieurs fois.

Prérequis :

  • Le Scénario 2 a été exécuté avec succès (des rapports ont déjà été synchronisés)

Étapes :

  1. Exécuter à nouveau la synchronisation manuelle (même requête que le Scénario 2)
  2. Lire le corps de la réponse JSON
  3. Vérifier dans SharePoint qu'aucun doublon n'est apparu

Résultat attendu :

  • La réponse HTTP est 200 OK
  • Le corps JSON indique que tous les rapports ont été ignorés : 
    { "uploaded": 0, "skipped": 3, "failed": 0 }
  • Aucun nouveau fichier n'est apparu dans SharePoint
  • Dans les journaux Azure, on lit : "Already claimed — skipping" pour chaque rapport
Résultat observé Statut
☐ ✅ Réussi   ☐ ❌ Échec   ☐ ⚠️ Partiel

Scénario 4 — Aucun rapport disponible dans Nethris¶

Description : Vérifier le comportement du système quand Nethris ne retourne aucun rapport (ex. en dehors du cycle de paie).

Prérequis :

  • Aucun rapport automatisé n'est disponible dans Nethris pour la période en cours

Étapes :

  1. Déclencher la synchronisation manuelle
  2. Lire le corps de la réponse JSON

Résultat attendu :

  • La réponse HTTP est 200 OK
  • Le corps JSON indique zéro rapport traité : 
    { "uploaded": 0, "skipped": 0, "failed": 0, "outcomes": [] }
  • Aucun fichier n'est créé dans SharePoint
  • Dans les journaux Azure, on lit : "Found 0 reports"
Résultat observé Statut
☐ ✅ Réussi   ☐ ❌ Échec   ☐ ⚠️ Partiel

Scénario 5 — Échec d'authentification Nethris¶

Description : Vérifier le comportement du système en cas d'identifiants Nethris incorrects ou expirés.

Prérequis :

  • Coordonner avec l'équipe technique pour configurer temporairement un mot de passe invalide dans Key Vault (environnement de test uniquement)

Étapes :

  1. Déclencher la synchronisation manuelle
  2. Observer la réponse HTTP
  3. Consulter les journaux Azure

Résultat attendu :

  • La réponse HTTP est 500 Internal Server Error

2.3 Comment déclencher la synchronisation manuellement¶

URL de déclenchement¶

GET https://{nom-de-la-function}.azurewebsites.net/api/sync/nethris-reports?code={clé-api}

L'équipe technique fournira l'URL complète avec la clé d'API pour chaque environnement (test, production).

Étapes avec un navigateur Web¶

  1. Copier l'URL complète fournie par l'équipe technique
  2. Coller l'URL dans la barre d'adresse du navigateur
  3. Appuyer sur Entrée
  4. Attendre la réponse (le navigateur peut rester en attente pendant quelques secondes à quelques minutes)
  5. Une fois la réponse affichée, lire le texte JSON pour connaître le résumé de la synchronisation

Que signifient les champs de la réponse ?¶

{
  "startedAtUtc": "2026-05-12T03:00:01Z",
  "completedAtUtc": "2026-05-12T03:00:45Z",
  "uploaded": 3,
  "skipped": 1,
  "failed": 0,
  "outcomes": [
    {
      "reportProdId": "45875",
      "reportName": "Payroll_Register",
      "status": "Uploaded",
      "sharePointPath": "FSources/Nethris/2026/05/01/Payroll_Register_45875_20260501_030001.pdf"
    },
    {
      "reportProdId": "45876",
      "reportName": "Employee_Contact_Source",
      "status": "AlreadySynced"
    }
  ]
}
Champ Signification
uploaded Nombre de rapports déposés avec succès dans SharePoint
skipped Nombre de rapports ignorés car déjà déposés précédemment
failed Nombre de rapports ayant échoué (à investiguer dans les journaux)
status: "Uploaded" Le rapport a été déposé avec succès
status: "AlreadySynced" Le rapport existait déjà — aucune action
status: "Failed" Une erreur s'est produite pour ce rapport
sharePointPath Chemin du fichier dans SharePoint (visible uniquement pour les rapports déposés)

Consulter les journaux Azure¶

Pour voir les détails d'une synchronisation (y compris les erreurs), l'équipe technique peut accéder à Application Insights dans le portail Azure :

  1. Ouvrir le portail Azure → Application Insights du projet Equipe Laurence
  2. Cliquer sur Journaux (Logs)
  3. Chercher les entrées liées à NethrisReportSyncService pour la période souhaitée
  4. En cas d'erreur, les journaux contiendront le détail complet de l'exception
