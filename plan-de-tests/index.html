Plan de tests — Equipe Laurence (Intégration Nethris → SharePoint)¶

1. Résumé des tests automatisés¶

Ce document recense les principaux tests automatisés de la solution. Au total, la suite compte plus de 200 méthodes de test (hors EquipeLaurence.AdSync.Tests) réparties sur sept projets (Core, Functions, Infrastructure, Infrastructure.Acs, Infrastructure.Twilio, IntegrationTests, Specs) ; seuls les projets Core, Functions, Infrastructure, IntegrationTests et Specs sont détaillés ci-dessous. Les tests des projets Infrastructure.Acs.Tests (AcsOptionsTests, AcsSmsClientTests), Infrastructure.Twilio.Tests (TwilioOptionsTests, TwilioSmsClientTests) et AdSync.Tests ne sont pas listés ici. La suite complète se lance avec dotnet test EquipeLaurence.sln ; les tests d'intégration portent le trait Category=Integration.

2. Plan de tests manuels / Tests d'acceptation¶

2.1 Contexte et prérequis généraux¶

À propos du système¶

Le système Equipe Laurence est une application automatisée hébergée dans Microsoft Azure. Selon la planification configurée (Nethris:SyncSchedule, toutes les minutes par défaut), elle se connecte au système de paie Nethris, récupère tous les rapports automatisés disponibles, et les dépose (copie racine + copie d'archive horodatée) dans une bibliothèque de documents SharePoint privée. Un registre interne empêche le dépôt en double d'un même rapport.

Le système peut également être déclenché manuellement via une URL sécurisée, ce qui permet de tester la synchronisation ou de récupérer des rapports en dehors du cycle automatique.

Prérequis pour l'exécution des tests d'acceptation¶

Avant de commencer les tests, s'assurer que les éléments suivants sont en place :

Prérequis Responsable Vérifié
L'application Azure Function est déployée (environnement de test ou production) Équipe technique ☐
Le mot de passe Nethris est dans Azure Key Vault ; les autres identifiants Nethris sont dans App Configuration Équipe technique ☐
L'identité gérée de la Function App a les droits nécessaires sur SharePoint Équipe technique ☐
La bibliothèque de documents SharePoint cible existe et est accessible Client ☐
Le registre de synchronisation (Azure Table Storage) est opérationnel Équipe technique ☐
La personne effectuant les tests a accès aux journaux Azure (Application Insights) Client ou équipe ☐
La clé d'API de la fonction HTTP est disponible Équipe technique ☐

2.2 Scénarios d'acceptation¶

Scénario 1 — Synchronisation automatique réussie¶

Description : Vérifier que la synchronisation automatique s'exécute correctement toutes les minutes et dépose les rapports dans SharePoint.

Prérequis :

  • L'application est déployée et le déclencheur automatique est activé (toutes les minutes)
  • Des rapports sont disponibles dans Nethris

2.3 Comment déclencher la synchronisation manuellement¶

URL de déclenchement¶

GET https://{nom-de-la-function}.azurewebsites.net/api/sync/nethris-reports?code={clé-api}

L'équipe technique fournira l'URL complète avec la clé d'API pour chaque environnement (test, production).

Étapes avec un navigateur Web¶

  1. Copier l'URL complète fournie par l'équipe technique
  2. Coller l'URL dans la barre d'adresse du navigateur
  3. Appuyer sur Entrée
  4. Attendre la réponse (le navigateur peut rester en attente pendant quelques secondes à quelques minutes)
  5. Une fois la réponse affichée, lire le texte JSON pour connaître le résumé de la synchronisation

Que signifient les champs de la réponse ?¶

{
  "startedAtUtc": "2026-05-12T03:00:01Z",
  "completedAtUtc": "2026-05-12T03:00:45Z",
  "uploaded": 3,
  "skipped": 1,
  "failed": 0,
  "outcomes": [
    {
      "reportProdId": "45875",
      "reportName": "Payroll_Register",
      "status": "Uploaded",
      "sharePointPath": "https://<tenant>.sharepoint.com/.../FSources/Nethris/ARCHIVES/Payroll_Register_20260501_030001.pdf"
    },
    {
      "reportProdId": "45876",
      "reportName": "Employee_Contact_Source",
      "status": "AlreadySynced"
    }
  ]
}
Champ Signification
uploaded Nombre de rapports déposés avec succès dans SharePoint
skipped Nombre de rapports ignorés car déjà déposés précédemment
failed Nombre de rapports ayant échoué (à investiguer dans les journaux)
status: "Uploaded" Le rapport a été déposé avec succès
status: "AlreadySynced" Le rapport existait déjà — aucune action
status: "Failed" Une erreur s'est produite pour ce rapport
sharePointPath Emplacement de la copie d'archive dans SharePoint (visible uniquement pour les rapports déposés)

Consulter les journaux Azure¶

Pour voir les détails d'une synchronisation (y compris les erreurs), l'équipe technique peut accéder à Application Insights dans le portail Azure :

  1. Ouvrir le portail Azure → Application Insights du projet Equipe Laurence
  2. Cliquer sur Journaux (Logs)
  3. Chercher les entrées liées à NethrisReportSyncService pour la période souhaitée
  4. En cas d'erreur, les journaux contiendront le détail complet de l'exception
