Guide de migration — Azure Communication Services → Twilio¶

Ce guide fournit une procédure étape par étape pour migrer votre système de SMS d'Equipe Laurence d'Azure Communication Services (ACS) vers Twilio, ainsi qu'une procédure de rollback en cas de problème.

Vue d'ensemble¶

La migration est non destructive et réversible : - Les anciennes configurations ACS restent intactes - La switch entre fournisseurs se fait via un simple paramètre de configuration - Les deux fournisseurs peuvent coexister temporairement pour les tests - Un rollback prend quelques secondes

Durée estimée : 30–45 minutes (dépend de votre réaction aux tests)

Prérequis¶

  • ✅ Compte Twilio actif avec API keys disponibles
  • ✅ Au moins un numéro SMS approuvé dans Twilio (E.164 format, ex: +15145550100)
  • ✅ Accès administrateur à Azure Key Vault pour l'environnement cible
  • ✅ Accès administrateur à App Configuration (ou délégation de droits)
  • ✅ L'environnement ACS restera intact et pourra être basculé après la migration si nécessaire
  • ✅ Plan de communication : avertir les utilisateurs des SMS de test potentiels

Étape 1 — Récupérer les credentials Twilio¶

  1. Connectez-vous à Twilio : 

    https://console.twilio.com/

  2. Accédez à Account > Security > API keys: 

    https://console.twilio.com/account/keys-credentials

  3. Copiez et conservez :

  4. Account SID — Identifiant unique du compte (ex: ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxx)
  5. Auth Token — Jeton secret (ex: your_auth_token_here) — ⚠️ Gardez-le confidentiel

  6. Phone Number — Numéro SMS à utiliser (ex: +15145550100)

  7. Vérifiez que le numéro est approuvé :

  8. Allez à Phone Numbers → Active Numbers ou Verified Numbers
  9. Assurez-vous que le numéro SMS pour SMS est présent et marqué SMS capable

Étape 2 — Provisionner les secrets Azure Key Vault¶

Option A — Via Azure Portal¶

  1. Ouvrez Key Vault :

  2. Allez à Azure Portal → Key Vaults → Sélectionnez le coffre de votre environnement

  3. Créez ou mettez à jour deux secrets :

Secret 1 : twilio-account-sid - Nom : twilio-account-sid - Valeur : Coller votre Account SID Twilio - Cliquez sur Create ou Update

Secret 2 : twilio-auth-token - Nom : twilio-auth-token - Valeur : Coller votre Auth Token Twilio - Cliquez sur Create ou Update

  1. Vérifiez l'accès :
  2. La Function App managed identity doit avoir la permission Get sur les secrets
  3. Allez à Access Control (IAM) → Confirmez que le rôle Key Vault Secrets User est assigné

Option B — Via Azure CLI¶

# Définissez vos variables
KEYVAULT_NAME="<your-keyvault-name>"
TWILIO_ACCOUNT_SID="<your-twilio-account-sid>"
TWILIO_AUTH_TOKEN="<your-twilio-auth-token>"

# Créez/mettez à jour les secrets
az keyvault secret set \
  --vault-name $KEYVAULT_NAME \
  --name twilio-account-sid \
  --value $TWILIO_ACCOUNT_SID

az keyvault secret set \
  --vault-name $KEYVAULT_NAME \
  --name twilio-auth-token \
  --value $TWILIO_AUTH_TOKEN

# Vérifiez
az keyvault secret list --vault-name $KEYVAULT_NAME --query "[?name=='twilio-account-sid' || name=='twilio-auth-token']"

Étape 3 — Mettre à jour App Configuration¶

Option A — Via Azure Portal¶

  1. Ouvrez App Configuration :

  2. Allez à Azure Portal → App Configuration → Sélectionnez le store de votre environnement

  3. Créez ou mettez à jour quatre clés :

Clé 1 : Sms:Provider - Clé : Sms:Provider - Valeur : Twilio - Type de contenu : text/plain - Cliquez sur Create

Clé 2 : Twilio:AccountSid (Référence Key Vault) - Clé : Twilio:AccountSid - Valeur : 

{"uri":"https://<your-keyvault>.vault.azure.net/secrets/twilio-account-sid/"}
- Type de contenu : application/vnd.microsoft.appconfig.keyvaultref+json;charset=utf-8 - Cliquez sur Create

Clé 3 : Twilio:AuthToken (Référence Key Vault) - Clé : Twilio:AuthToken - Valeur : 

{"uri":"https://<your-keyvault>.vault.azure.net/secrets/twilio-auth-token/"}
- Type de contenu : application/vnd.microsoft.appconfig.keyvaultref+json;charset=utf-8 - Cliquez sur Create

Clé 4 : Twilio:FromNumber (Texte brut) - Clé : Twilio:FromNumber - Valeur : Votre numéro SMS Twilio (ex: +15145550100) - Type de contenu : text/plain - Cliquez sur Create

  1. Vérifiez les configurations :
  2. Allez à Configuration explorer
  3. Assurez-vous que Sms:Provider = Twilio et les trois clés Twilio sont présentes

Option B — Via Azure CLI¶

# Définissez vos variables
APPCONFIG_NAME="<your-appconfig-name>"
KEYVAULT_URL="https://<your-keyvault>.vault.azure.net"
TWILIO_FROM_NUMBER="+15145550100"

# Créez/mettez à jour les clés
az appconfig kv set \
  --name $APPCONFIG_NAME \
  --key "Sms:Provider" \
  --value "Twilio" \
  --content-type "text/plain" \
  --yes

az appconfig kv set \
  --name $APPCONFIG_NAME \
  --key "Twilio:AccountSid" \
  --value "{\"uri\":\"${KEYVAULT_URL}/secrets/twilio-account-sid/\"}" \
  --content-type "application/vnd.microsoft.appconfig.keyvaultref+json;charset=utf-8" \
  --yes

az appconfig kv set \
  --name $APPCONFIG_NAME \
  --key "Twilio:AuthToken" \
  --value "{\"uri\":\"${KEYVAULT_URL}/secrets/twilio-auth-token/\"}" \
  --content-type "application/vnd.microsoft.appconfig.keyvaultref+json;charset=utf-8" \
  --yes

az appconfig kv set \
  --name $APPCONFIG_NAME \
  --key "Twilio:FromNumber" \
  --value "$TWILIO_FROM_NUMBER" \
  --content-type "text/plain" \
  --yes

# Vérifiez
az appconfig kv list --name $APPCONFIG_NAME --key "Sms:*" --key "Twilio:*"

Étape 4 — Déploiement Bicep (optionnel, recommandé)¶

Si vous avez une infrastructure as code, mettez à jour et redéployez le template Bicep pour documenter la décision :

Mettre à jour .bicepparam¶

Modifiez infra/parameters/{env}.bicepparam (ex: dev.bicepparam, test.bicepparam, prod.bicepparam) :

param smsProvider = 'Twilio'
param twilioAccountSid = '<your-twilio-account-sid>'
param twilioAuthToken = '<your-twilio-auth-token>'
param twilioFromNumber = '+15145550100'

Redéployer¶

az deployment group create \
  --name "sms-migration-to-twilio-$(date +%s)" \
  --resource-group <your-resource-group> \
  --template-file infra/main.bicep \
  --parameters infra/parameters/{env}.bicepparam \
  --query "properties.outputs"

⚠️ Remarque : Si vous ne redéployez PAS Bicep, les clés App Configuration configurées manuellement à l'Étape 3 resteront valides. Cependant, les redéployer via Bicep garantit une source unifiée de vérité.

Étape 5 — Configurer le webhook Twilio entrant (optionnel)¶

Si vous souhaitez capturer les SMS entrants (réponses STOP, données SMS, etc.) :

  1. Trouvez l'URL de votre Function App : 

    https://{functionApp}.azurewebsites.net/api/sms/inbound/twilio
    (Remplacez {functionApp} par le nom de votre application fonction)

  2. Dans Twilio Console :

  3. Allez à Messaging → Services → Sélectionnez votre service SMS
  4. Sous Inbound Settings, activez Inbound Message Webhook
  5. Collez l'URL complète ci-dessus
  6. Assurez-vous que la méthode est POST

  7. Cliquez sur Save

  8. Test de webhook (optionnel) :

  9. Allez à Webhook Logs et envoyez un SMS de test à votre numéro Twilio
  10. Vérifiez que la Function App reçoit le webhook (vérifiez les logs Application Insights)

Étape 6 — Tester la configuration Twilio¶

6a — Vérifier les logs de démarrage¶

  1. Via Application Insights : 

    Azure Portal → Application Insights → Logs
    Exécutez : 
    traces 
| where message contains "Twilio" or message contains "SMS"
| project timestamp, message, severityLevel 
| order by timestamp desc 
| limit 30

  2. Cherchez les messages de succès :

  3. "Successfully initialized TwilioSmsClient"
  4. "Twilio provider configured"

6b — Envoyer un SMS de test¶

Via l'API HTTP (recommandé) :

# Définir les variables
FUNCTION_APP_URL="https://{functionApp}.azurewebsites.net"
LOCATION_CODE="MTL"  # Code du bureau avec destinataires test
MESSAGE="TEST: Migration Twilio réussie - $(date)"

# Envoyer
curl -X POST "${FUNCTION_APP_URL}/api/notifications/sms/send-by-bureau" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "locationCode=${LOCATION_CODE}&messageBody=${MESSAGE}" \
  -v

Via le formulaire web (optionnel) : 

https://{functionApp}.azurewebsites.net/api/notifications/sms/form
- Sélectionnez le bureau - Saisissez un message de test - Cliquez sur Envoyer les SMS

6c — Vérifier la livraison¶

  1. Application Insights : 

    traces 
| where message contains "SMS" and message contains "sent"
| project timestamp, message, customDimensions
| order by timestamp desc 
| limit 10

  2. Twilio Console :

  3. Allez à Messaging → Logs ou SMS Logs
  4. Cherchez les messages envoyés à votre heure de test

  5. Vérifiez les statuts : Sent, Delivered, etc.

  6. Table Storage (Azure Portal) :

  7. Ouvrez l'onglet Storage Account pour votre environnement
  8. Allez à Tables → SmsAudit
  9. Vérifiez que des enregistrements d'audit sont créés avec les TwilioSid (ex: SM123abc...)

Étape 7 — Validation complète¶

Checklist de validation¶

  • ✅ Sms:Provider = "Twilio" dans App Configuration
  • ✅ Twilio:AccountSid, Twilio:AuthToken résolvent correctement depuis Key Vault
  • ✅ Twilio:FromNumber est défini avec le bon numéro E.164
  • ✅ Un SMS de test a été envoyé et livré avec succès
  • ✅ Les logs Application Insights montrent TwilioSmsClient initialisé
  • ✅ Table Storage SmsAudit contient des enregistrements avec les TwilioSid
  • ✅ Aucune erreur dans la console Twilio ou les logs Azure

Tester les cas limites¶

Cas de test Procédure Résultat attendu
STOP/ARRET reçu Envoyez STOP à votre numéro Twilio, puis testez un envoi Le recipient est dans la table OptOut, SMS non envoyé
Idempotence Envoyez deux fois le même Idempotency-Key Deuxième réponse rejouée, pas de double envoi
Numéro invalide Configurer Twilio:FromNumber avec un numéro non approuvé Erreur "number not enabled" ou similaire dans les logs
Credentials invalides Scénario de rotation manuelle — mettre à jour Key Vault avec des credentials fictifs Erreur d'authentification 401 dans Application Insights

Procédure de rollback¶

En cas de problème, vous pouvez revenir à ACS en quelques secondes :

Rollback complet (recommandé)¶

# Via Azure CLI
az appconfig kv set \
  --name <appconfig-name> \
  --key "Sms:Provider" \
  --value "Acs" \
  --content-type "text/plain" \
  --yes

Ou via le Portal : - App Configuration → Configuration explorer - Modifier Sms:Provider → Valeur = Acs → Save

Rollback Bicep¶

Si vous aviez redéployé Bicep à l'Étape 4 :

# Revenez à la version précédente du .bicepparam
param smsProvider = 'Acs'

Redéployez : 

az deployment group create \
  --resource-group <your-resource-group> \
  --template-file infra/main.bicep \
  --parameters infra/parameters/{env}.bicepparam

Délai avant prise d'effet¶

  • App Configuration seul : Les changements sont appliqués immédiatement lors du prochain redémarrage de la Function App
  • Bicep redéployé : Les changements prennent effet lors de la prochaine exécution de fonction (< 1 minute)

Dépannage pendant la migration¶

Symptôme Cause probable Solution
Erreur 401 AuthenticationError Credentials Twilio invalides Vérifiez le Account SID et Auth Token via https://console.twilio.com
Erreur "The phone number X is not capable of sending SMS" Le FromNumber n'est pas approuvé pour SMS dans Twilio Allez à Phone Numbers → Active Numbers et vérifiez que SMS est activé
Configuration toujours utilise ACS Sms:Provider n'a pas changé ou reste vide Confirmez que Sms:Provider = Twilio est défini dans App Config
Key Vault secret not found Secrets twilio-account-sid ou twilio-auth-token manquants Vérifiez les noms des secrets (case-sensitive) et que le managed identity a Get access
Fonction rechute sur "Disabled SMS Client" Condition de fallback : ACS n'est pas entièrement configuré mais n'est pas nettoyé Assurez-vous que Sms:Provider est explicitement défini, pas basé sur la rétrocompatibilité

Après la migration¶

Observations¶

  • Les anciennes configurations ACS restent — vous pouvez les laisser ou les nettoyer
  • L'envoi de SMS précédents ne sera pas affecté — seuls les nouveaux SMS utilisent Twilio
  • Les logs d'audit conservent les anciens AcsSid — les nouveaux SMS seront marqués avec des TwilioSid

Nettoyage optionnel¶

Si vous souhaitez nettoyer complètement ACS :

  1. Supprimer les clés App Configuration obsolètes :
  2. Acs:ConnectionString

  3. Acs:PhoneNumber

  4. Supprimer les ressources Azure ACS (optionnel) : 

    az communication list --query "[?name=='eql-{env}-acs']" --output table
# Puis supprimez via le Portal si nécessaire

  5. Mettre à jour Bicep :

  6. Définissez param smsProvider = 'Twilio' de manière permanente
  7. Vous pouvez laisser le module acsService.bicep pour la rétrocompatibilité
