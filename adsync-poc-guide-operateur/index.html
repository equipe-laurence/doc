adsync-poc — Guide de l'opérateur¶

Statut : premier POC, jamais exécuté contre un vrai Active Directory. L'outil a été validé uniquement par des tests automatiques (annuaire simulé) et sur un poste non joint au domaine, où check échoue proprement. Votre exécution est le premier vrai test : si quelque chose échoue, c'est une information utile — copiez simplement la sortie de la console (voir « Quoi nous renvoyer »).

Ce que fait l'outil¶

adsync-poc.exe est un petit programme console, autonome (rien à installer), qui :

  1. teste qu'il peut joindre Active Directory avec l'identité Windows de la personne qui le lance (aucun mot de passe n'est demandé ni stocké) ;
  2. trouve un objet : un utilisateur (code = préfixe du courriel, ex. jdoe) ou, avec --dn, n'importe quel objet (poste, groupe…) désigné par son DN exact ;
  3. liste ses attributs (list), lit et modifie UN seul attribut, avec simulation par défaut, sauvegarde de l'ancienne valeur et possibilité de revenir en arrière.

Un seul objet et un seul attribut par exécution (list affiche tous les attributs d'un seul objet, en lecture seule). Pas de joker, pas de boucle. Les attributs d'identité et de sécurité (mail, userPrincipalName, sAMAccountName, memberOf, userAccountControl, cn, name, etc.) sont refusés par défaut ; ils ne deviennent accessibles que si vous ajoutez explicitement --allow-sensitive (voir « Attributs sensibles »). Les attributs de mots de passe et secrets sont toujours refusés, même avec --allow-sensitive, pour get, list, set et restore : tout nom contenant pwd ou password (ex. unicodePwd, userPassword, unixUserPassword) et les attributs LAPS (ms-Mcs-AdmPwd, msLAPS-Password, msLAPS-EncryptedPassword, msLAPS-EncryptedPasswordHistory).

Prérequis¶

  • Une machine Windows jointe au domaine (ou directement un contrôleur de domaine), session ouverte avec un compte du domaine (pas un compte local).
  • Pour check, get et list : un compte du domaine ordinaire suffit (lecture).
  • Pour set --apply : le compte doit avoir le droit d'écrire l'attribut visé sur l'utilisateur visé (délégation AD ou administrateur du domaine).
  • Accès réseau au contrôleur de domaine : TCP 389 (ou 636 avec --ldaps), DNS fonctionnel, heure synchronisée.
  • Ouvrir une invite de commandes (ou PowerShell) dans le dossier où se trouve adsync-poc.exe.

⚠ Avertissements¶

  • C'est un annuaire de production. Faites d'abord vos essais avec un attribut sans importance (par exemple extensionAttribute15 ou info) sur votre propre compte ou un compte de test.
  • Lancez d'abord get sur l'attribut, avec le même compte Windows que pour set. Le résultat (absent) ou (absent ou vide) peut signifier : l'attribut n'existe pas dans le schéma AD, il est vide, ou ce compte n'a pas le droit de le lire. L'outil ne peut pas faire la différence ; l'outil le rappelle dans get et dans la simulation de set.
  • Les attributs binaires (photo, GUID…) sont refusés par get/set (code 3) : l'outil ne gère que le texte. list les affiche sous la forme <binaire, N octets> sans en montrer le contenu.
  • set ne gère que les attributs mono-valués. Un attribut multi-valué (ex. proxyAddresses, memberOf) peut être lu (get, list) mais sa modification est refusée (code 3) : c'est une limite volontaire de ce POC.
  • Commencez toujours par la simulation (sans --apply) : elle n'écrit rien.
  • Conservez le fichier de sauvegarde adsync-poc-backup-<date>.txt (créé à côté de l'exécutable) : il contient l'ancienne valeur en clair. Ne le partagez pas s'il contient une donnée sensible.
  • get, list, set et restore affichent des valeurs dans la console, car vous les avez demandés explicitement. Ces valeurs peuvent être sensibles : relisez la sortie avant de l'envoyer.
  • L'outil ne journalise aucune valeur ailleurs que dans cette sortie console et dans le fichier de sauvegarde.

Les commandes, dans l'ordre¶

Remplacez jdoe par le code de l'utilisateur de test et extensionAttribute15 par l'attribut de test.

1. Vérifier l'accès (lecture seule)¶

adsync-poc check

Affiche : l'identité Windows (DOMAINE\utilisateur), le nom de la machine, si elle est jointe à un domaine ou est un contrôleur de domaine, le résultat de la connexion/authentification (Negotiate, identité courante), la base de recherche utilisée (détectée automatiquement via le RootDSE, defaultNamingContext) et RÉSULTAT : OK ou un message d'échec avec des pistes. Options : --dc <hôte>, --search-base "<DN>", --ldaps.

2. Lire un attribut¶

adsync-poc get --user jdoe --attribute extensionAttribute15

Cherche l'utilisateur : d'abord sAMAccountName, puis préfixe de mail / userPrincipalName. Un seul résultat est exigé (sinon : « aucun » ou « ambigu » avec la liste des comptes). Affiche le DN, activé/désactivé et la valeur actuelle.

Pour viser n'importe quel objet (poste, groupe, utilisateur…), remplacez --user jdoe par son DN exact (option --dn, exclusive avec --user) : adsync-poc get --dn "CN=PC-001,OU=Postes,DC=contoso,DC=local" --attribute location. Avec --search-base, le DN doit se trouver sous cette base, sinon il est refusé. --dn s'utilise aussi avec list et set.

2 bis. Lister tous les attributs d'un objet (lecture seule)¶

adsync-poc list --user jdoe
adsync-poc list --dn "CN=PC-001,OU=Postes,DC=contoso,DC=local" --schema

Affiche le DN, l'objectGUID, puis tous les attributs que ce compte peut lire, avec leurs valeurs, en deux sections : attributs natifs AD puis attributs personnalisés / extensions (extensionAttributeN, attributs ajoutés au schéma de l'organisation…). Ce classement est indicatif. Chaque ligne indique la cardinalité (mono / multi, ? si inconnue). Les mots de passe et secrets (LAPS…) apparaissent comme <masqué>, les valeurs binaires comme <binaire, N octets>, les valeurs très longues sont tronquées. Un attribut que ce compte n'a pas le droit de lire n'apparaît pas.

Avec --schema, list ajoute aussi les attributs autorisés par le schéma mais vides sur cet objet (allowedAttributes), leur cardinalité réelle, et une colonne : modifiable (ce compte peut l'écrire : allowedAttributesEffective), modifiable (sensible) (modifiable seulement avec --allow-sensitive), non modifiable ou interdit (mots de passe/secrets : jamais). Cela permet de repérer les attributs personnalisés vides disponibles pour set. Si le schéma n'est pas lisible, --schema est ignoré avec un avertissement.

3. Simuler une modification (aucune écriture)¶

adsync-poc set --user jdoe --attribute extensionAttribute15 --value "valeur-de-test"

Affiche ce qui serait changé : DN, attribut, ancienne valeur -> nouvelle valeur. Rien n'est écrit. (Pour effacer l'attribut : --clear à la place de --value. Une valeur vide est refusée.)

4. Appliquer la modification¶

adsync-poc set --user jdoe --attribute extensionAttribute15 --value "valeur-de-test" --apply

L'outil affiche le résumé puis demande de taper le code utilisateur (jdoe) — ou, avec --dn, le nom de l'objet affiché à l'écran — pour confirmer. Ensuite il : sauvegarde l'ancienne valeur dans adsync-poc-backup-<date-heure>.txt (à côté de l'exécutable), écrit, relit et vérifie, puis affiche SUCCÈS ou ÉCHEC. (--yes supprime uniquement la question de confirmation.) Si une erreur ou un Ctrl+C survient après le début de l'écriture (y compris pendant la relecture), l'outil affiche que l'écriture a peut-être été appliquée : vérifiez avec get ; le chemin du fichier de sauvegarde est rappelé. L'utilisateur doit avoir un objectGUID dans l'annuaire, sinon l'opération est refusée.

4 bis. Attributs sensibles (--allow-sensitive)¶

Par défaut, get, set et restore refusent (code 3) les attributs d'identité et de sécurité (mail, userPrincipalName, sAMAccountName, memberOf, userAccountControl, cn, name…). Le message d'erreur mentionne --allow-sensitive. En ajoutant cette option, vous les autorisez explicitement et à vos risques :

adsync-poc set --user jdoe --attribute mail --value jdoe@contoso.com --allow-sensitive
adsync-poc set --user jdoe --attribute mail --value jdoe@contoso.com --allow-sensitive --apply

Un avertissement bien visible (ATTRIBUT SENSIBLE) est affiché dans le résumé de chaque écriture ; la simulation par défaut, la confirmation tapée, la sauvegarde (qui contient alors aussi ces valeurs sensibles), la relecture de vérification et l'objectGUID obligatoire restent actifs. Modifier mail, userPrincipalName ou sAMAccountName peut empêcher des utilisateurs de se connecter ou casser la messagerie et les synchronisations : n'utilisez cette option que sur un compte de test et en connaissance de cause. Pour revenir en arrière, restore d'une sauvegarde sensible exige aussi --allow-sensitive (la commande exacte est rappelée après SUCCÈS). Les mots de passe et secrets (unicodePwd, userPassword, ms-Mcs-AdmPwd, msLAPS-*…) restent toujours refusés.

5. Revenir en arrière¶

adsync-poc restore --backup adsync-poc-backup-20261009-153000.txt
adsync-poc restore --backup adsync-poc-backup-20261009-153000.txt --apply

La première commande simule, la seconde remet l'ancienne valeur (après confirmation). Le fichier de sauvegarde n'est pas cru sur parole : restore retrouve l'objet dans l'annuaire (par la recherche habituelle, option --search-base possible, ou directement par son DN si la sauvegarde a été faite avec --dn) et exige que son DN et son objectGuid soient identiques à ceux du fichier ; une sauvegarde sans objectGuid est refusée (code 3). Le code à taper pour confirmer est le sAMAccountName réel de l'utilisateur trouvé (ou le nom de l'objet pour une sauvegarde --dn), affiché à l'écran avec son DN. Un nouveau fichier de sauvegarde est créé avant la remise en place.

Codes de sortie¶

Code Signification
0 Succès
1 Erreur (connexion, annuaire, écriture, vérification)
2 Arguments invalides
3 Refusé par un garde-fou (attribut sensible sans --allow-sensitive, mot de passe/secret, utilisateur ambigu, attribut multi-valué ou binaire, DN hors de --search-base, sauvegarde sans objectGuid ou ne correspondant pas à l'annuaire…)
4 Annulé (confirmation non donnée)

En cas d'échec — causes les plus probables à la première exécution¶

Symptôme dans la console Cause probable Que faire
check : « Impossible de joindre l'annuaire… (code LDAP 81 / 91 / 82) » DNS, pare-feu, machine non jointe, ou serveur qui exige LDAPS Essayer --dc <nom-du-DC>, puis --ldaps. Vérifier que la session est un compte du domaine.
ERREUR … (code LDAP 8 ou 13) ou 49 Signature/chiffrement LDAP exigés autrement, ou authentification refusée Relancer avec --ldaps.
get : « Aucun utilisateur trouvé » ou « ambigu » Code différent du préfixe de courriel, ou plusieurs comptes Vérifier le code ; préciser --search-base "OU=…,DC=…".
set --apply : « ÉCHEC pendant l'écriture … (code LDAP 50) » Le compte n'a pas le droit d'écrire cet attribut sur cet utilisateur Utiliser un compte délégué/administrateur, ou un autre attribut. En principe aucune modification n'a eu lieu, mais l'outil demande de le vérifier avec get.
set --apply : « (code LDAP 16/17 ou 21/19) » Attribut inexistant dans le schéma, ou valeur au mauvais format Vérifier le nom LDAP et le format de la valeur.
get ne trouve pas un utilisateur pourtant présent Limite de taille/ base trop restreinte Indiquer --search-base "DC=…,DC=…".

Quoi nous renvoyer¶

  • La sortie complète de la console de chaque commande lancée (copier-coller du texte, y compris les lignes ERREUR), ainsi que le code de sortie (echo %ERRORLEVEL% sous cmd, $LASTEXITCODE sous PowerShell).
  • Si possible, indiquez l'attribut et le type de valeur testés.
  • Ne renvoyez pas le fichier adsync-poc-backup-*.txt sauf demande explicite (il contient des valeurs en clair).
  • Masquez ce qui est confidentiel (noms, valeurs) avant l'envoi si nécessaire.

Limites connues de ce POC¶

  • Jamais exécuté contre un vrai Active Directory avant votre test.
  • Attributs mono-valués texte uniquement pour set/restore ; les attributs binaires (valeur illisible, caractère U+FFFD) ou multi-valués sont refusés (list et get les lisent, sans afficher le binaire).
  • Aucune normalisation du code : les accents sont refusés (code de sortie 2) ; seuls les lettres non accentuées, chiffres, ., _, - et l'apostrophe sont acceptés.
  • Aucune planification, aucune source de données externe : une seule modification manuelle à la fois.

Note pour les développeurs¶

Le paquet à remettre à l'opérateur se construit avec scripts\publish-adsync-poc.ps1 : il publie un exécutable unique autonome win-x64 dans artifacts\adsync-poc, y copie ce guide sous le nom LISEZMOI.txt et crée artifacts\adsync-poc.zip. Ne modifiez pas LISEZMOI.txt à la main : modifiez ce guide puis relancez le script.
