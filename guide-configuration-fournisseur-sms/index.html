Guide de configuration du fournisseur SMS¶

Ce guide décrit comment configurer et gérer les fournisseurs SMS dans Equipe Laurence — Twilio, Azure Communication Services (ACS), ou désactiver les SMS complètement.

Vue d'ensemble¶

Le système Equipe Laurence supporte plusieurs fournisseurs SMS pour l'envoi de notifications d'urgence. La sélection du fournisseur s'effectue via le paramètre de configuration Sms:Provider :

Fournisseur Valeur config Comportement
Twilio "Twilio" SMS actifs — messages envoyés via l'API Twilio (TwilioSmsClient)
Azure Communication Services "Acs" Envoi non câblé — le Function App ne référence plus le client ACS ; la valeur "Acs" enregistre le DisabledSmsClient (legacy, rollback d'infra uniquement)
Désactivé "Disabled", vide ou absent SMS silencieux — les fonctions s'exécutent mais aucun message n'est envoyé (chaque destinataire reçoit l'erreur SmsDisabled, la réponse HTTP reste 200)

La valeur par défaut est Disabled (SmsOptions.Provider vide, paramètre Bicep smsProvider = 'Disabled'). Les options Twilio:* sont validées au démarrage quel que soit le fournisseur retenu.

Configuration Twilio (fournisseur recommandé)¶

Prérequis¶

  • Compte Twilio actif avec numéro SMS approuvé (E.164 format, ex: +15145550100)
  • Accès à Azure Key Vault et App Configuration pour l'environnement cible
  • Permissions d'administrateur Azure pour configurer Bicep

Étape 1 — Créer/ajouter les secrets Key Vault¶

Deux secrets doivent être créés ou mis à jour dans Key Vault :

Secret Description Format
twilio-account-sid Identifiant de compte Twilio Copier depuis https://console.twilio.com/account/keys-credentials
twilio-auth-token Jeton d'authentification Twilio Copier depuis https://console.twilio.com/account/keys-credentials

Via Azure Portal : 1. Ouvrez Key Vault pour votre environnement 2. Cliquez sur Secrets → Generate/Import 3. Créez/mettez à jour twilio-account-sid avec le Account SID Twilio 4. Créez/mettez à jour twilio-auth-token avec l'Auth Token Twilio

Via CLI : 

az keyvault secret set \
  --vault-name <your-keyvault-name> \
  --name twilio-account-sid \
  --value <your-twilio-account-sid>

az keyvault secret set \
  --vault-name <your-keyvault-name> \
  --name twilio-auth-token \
  --value <your-twilio-auth-token>

Étape 2 — Configurer App Configuration¶

App Configuration doit contenir quatre clés Twilio. Elles sont créées automatiquement lors du déploiement Bicep, mais vous pouvez les vérifier/modifier manuellement :

Clé Valeur Type
Sms:Provider Twilio Texte brut
Twilio:AccountSid Référence Key Vault : twilio-account-sid Référence KV
Twilio:AuthToken Référence Key Vault : twilio-auth-token Référence KV
Twilio:FromNumber Numéro SMS Twilio (ex: +15145550100) Texte brut

Via Azure Portal : 1. Ouvrez App Configuration pour votre environnement 2. Cliquez sur Configuration explorer → Create → Key-value 3. Ajoutez/mettez à jour chaque clé ci-dessus 4. Pour les références Key Vault, sélectionnez Content Type = application/vnd.microsoft.appconfig.keyvaultref+json;charset=utf-8 et saisissez : 

{"uri":"https://<your-keyvault>.vault.azure.net/secrets/twilio-account-sid/"}

Étape 3 — Déploiement Bicep (optionnel)¶

Si vous redéployez l'infrastructure complète, mettez à jour le fichier .bicepparam de votre environnement :

infra/parameters/{env}.bicepparam: 

param smsProvider = 'Twilio'
param twilioFromNumber = '+15145550100'                // Plaintext in App Config
// twilioAccountSidValue / twilioAuthTokenValue : paramètres @secure, à fournir au déploiement
// (ex. --parameters twilioAccountSidValue=... twilioAuthTokenValue=...) ; stockés dans Key Vault

Ensuite, déployez (le workflow infra-deploy.yml ne transmet pas les valeurs Twilio : créez les secrets Key Vault manuellement si elles ne sont pas passées en paramètre) : 

az deployment group create \
  --resource-group <your-resource-group> \
  --template-file infra/main.bicep \
  --parameters infra/parameters/{env}.bicepparam

Étape 4 — Configuration du webhook entrant (optionnel)¶

Si vous souhaitez recevoir des SMS entrants (par exemple, pour capturer les réponses STOP/START des utilisateurs), configurez un webhook Twilio :

  1. Trouvez votre URL Function App : 

    https://{functionApp}.azurewebsites.net/api/sms/inbound/twilio

  2. Dans la console Twilio :

  3. Allez à Messaging → Services → Sélectionnez votre service SMS
  4. Sous Inbound Settings, activez Inbound Message Webhook
  5. Collez l'URL complète ci-dessus

  6. Assurez-vous que la méthode HTTP est POST

  7. Validation HMAC-SHA1 :

  8. Twilio signe chaque requête webhook avec un en-tête X-Twilio-Signature
  9. L'endpoint TwilioInboundSmsFunction valide automatiquement cette signature
  10. Aucune configuration supplémentaire n'est requise — la validation utilise le AuthToken depuis TwilioOptions

Étape 5 — Validation¶

Testez que Twilio est correctement configuré :

  1. Via les journaux Application Insights :
  2. Allez à Application Insights → Logs

  3. Exécutez cette requête KQL : 

    traces 
| where message contains "Twilio" 
| project timestamp, message, severityLevel 
| order by timestamp desc 
| limit 20

  4. Envoyez un SMS de test :

  5. Ouvrez le formulaire GET /api/notifications/sms/form dans le navigateur (authentification Entra ID requise) et envoyez un message à un bureau de test

  6. Ou appelez POST /api/notifications/sms/send-by-bureau (voir Guide API SMS)

  7. Vérifiez l'envoi :

  8. Consultez GET /api/sms/broadcasts ou la table SmsAuditLog dans Table Storage
  9. Vérifiez que les SID Twilio sont enregistrés dans MessageIds (ex: SM123abc...)
  10. Note : le suivi de livraison (SmsDeliveryStatus) n'est alimenté que par le callback ACS ; aucun callback de statut Twilio n'est implémenté

Configuration Azure Communication Services (ACS)¶

Note de dépréciation¶

Azure Communication Services n'est plus câblé à l'envoi : avec Sms:Provider = "Acs", le Function App enregistre le DisabledSmsClient (aucun SMS n'est envoyé). Le projet EquipeLaurence.Infrastructure.Acs existe toujours mais n'est pas référencé par le Function App ; seule la fonction de rapports de livraison AcsDeliveryStatus (POST /api/sms/delivery-status, Event Grid) reste active. Twilio est le fournisseur à utiliser.

Configuration¶

Côté infrastructure uniquement, le module acsService.bicep est conservé pour un éventuel rollback :

infra/parameters/{env}.bicepparam: 

param smsProvider = 'Acs'

Les secrets ACS et les clés App Configuration (Acs:ConnectionString, Acs:PhoneNumber) sont alors provisionnés, mais n'ont aucun effet sur l'envoi.

Détection rétroactive (legacy)¶

Pour la compatibilité avec d'anciennes configurations : - Si Sms:Provider n'est pas défini OU est vide - ET les clés ACS sont entièrement configurées (Acs:ConnectionString + Acs:PhoneNumber) - GetSmsProvider retourne "Acs" — ce qui, comme ci-dessus, enregistre le DisabledSmsClient

Il faut donc définir explicitement Sms:Provider = "Twilio" pour envoyer des SMS.

Désactiver les SMS¶

Pour désactiver complètement les SMS (les fonctions s'exécutent mais aucun message n'est envoyé), configurez :

Sms:Provider = "Disabled"

Ou laissez-le vide/absent ET assurez-vous qu'aucune clé ACS n'est configurée (sinon la détection rétroactive retourne "Acs", qui désactive aussi l'envoi).

Quand désactiver : - Environnements de développement/test locaux - Éviter les frais de SMS en dev - Préserver les quotas SMS en production lors de la maintenance

Les journaux indiqueront SMS send skipped because the SMS feature is disabled for this environment (avertissement du DisabledSmsClient) et chaque destinataire recevra l'erreur SmsDisabled dans la réponse.

Ajouter un nouveau fournisseur¶

Si vous souhaitez ajouter un nouveau fournisseur SMS (Signal, Nexmo, etc.), suivez ce patron :

1. Créer le projet Infrastructure¶

src/EquipeLaurence.Infrastructure.{Provider}/
├── Configuration/
│   └── {Provider}Options.cs          // POCO pour les settings
├── Clients/
│   └── {Provider}SmsClient.cs       // Implémentation ISmsClient
└── EquipeLaurence.Infrastructure.{Provider}.csproj

Le projet doit ensuite être référencé par EquipeLaurence.Functions.csproj (comme Infrastructure.Twilio).

2. Implémenter ISmsClient¶

ISmsClient ne doit jamais lever d'exception d'envoi : les erreurs sont retournées dans SmsSendResult (Error = classification sans PII). Voir TwilioSmsClient comme référence.

using EquipeLaurence.Core.Clients;
using EquipeLaurence.Core.Models;
using Microsoft.Extensions.Logging;

public sealed class YourProviderSmsClient : ISmsClient
{
    private readonly ILogger<YourProviderSmsClient> _logger;
    private readonly IOptions<YourProviderOptions> _options;

    public YourProviderSmsClient(
        ILogger<YourProviderSmsClient> logger,
        IOptions<YourProviderOptions> options)
    {
        _logger = logger;
        _options = options;
    }

    public async Task<SmsSendResult> SendSmsAsync(
        string toE164,
        string body,
        string broadcastIdempotencyKey,
        CancellationToken cancellationToken = default)
    {
        try
        {
            // Call your provider's API here
            _logger.LogInformation(
                "SMS sent to {PhoneNumber} via {Provider}",
                MaskPhoneNumber(toE164),
                "YourProvider");
            return new SmsSendResult { Success = true, MessageId = "<provider-message-id>" };
        }
        catch (Exception ex) when (ex is not OperationCanceledException)
        {
            _logger.LogError(ex, "Failed to send SMS via {Provider}", "YourProvider");
            return new SmsSendResult { Success = false, Error = "UnexpectedError" };
        }
    }

    private static string MaskPhoneNumber(string phoneNumber)
        => phoneNumber.Length > 4 
            ? $"****{phoneNumber[^4..]}" 
            : "****";
}

3. Enregistrer dans FunctionAppStartup.cs¶

switch (smsProvider.ToLowerInvariant())
{
    case "twilio":
        services.AddSingleton<ISmsClient, TwilioSmsClient>();
        break;
    case "yourprovider":  // Nouveau cas
        services
            .AddOptions<YourProviderOptions>()
            .BindConfiguration(YourProviderOptions.SectionName)
            .ValidateDataAnnotations()
            .ValidateOnStart();
        services.AddSingleton<ISmsClient, YourProviderSmsClient>();
        break;
    // ... autres cas ...
}

4. Créer le module Bicep¶

// infra/modules/{provider}Provider.bicep
param keyVaultUri string
param {provider}ApiKey string = ''
param {provider}FromNumber string = ''

// ... Ressources pour provisionner les secrets ...

output apiKeySecretName string = '{provider}-api-key'

5. Mettre à jour main.bicep¶

module {provider}Provider = './modules/{provider}Provider.bicep' = if (smsProvider == '{Provider}') {
  name: '{provider}Provider'
  params: {
    keyVaultUri: keyVault.outputs.uri
    // ...
  }
}

6. Ajouter les tests¶

Créez une suite de tests dans tests/EquipeLaurence.Infrastructure.{Provider}.Tests/ suivant le même patron que TwilioSmsClientTests.

Dépannage¶

Symptôme Cause probable Solution
Erreur SmsDisabled dans la réponse Sms:Provider manquant, vide, Disabled ou Acs Configurez explicitement Sms:Provider = Twilio dans App Config
Le Function App ne démarre pas (OptionsValidationException) Twilio:AccountSid, Twilio:AuthToken ou Twilio:FromNumber manquant Vérifiez App Configuration / Key Vault / local.settings.json
Erreur "Key Vault secret not found" Secret manquant (twilio-account-sid, etc.) Vérifiez que les secrets existent dans Key Vault
TwilioError:20003 / TwilioError:20404 Identifiants Twilio incorrects Régénérez les identifiants dans Twilio Console
Webhook Twilio répond 403 Signature X-Twilio-Signature invalide (URL publique ou Twilio:AuthToken incorrect) Vérifiez l'URL complète configurée dans Twilio et le AuthToken
SMS émis silencieusement mais pas reçus Quota atteint, numéro de téléphone non approuvé Vérifiez les logs Twilio, contactez le support
Logs montrent "SMS feature is disabled" Configuration a basculé vers "Disabled" ou "Acs" Confirmez que Sms:Provider = "Twilio" est défini
